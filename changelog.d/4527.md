- **chore(orchestrate): 契約の gates に `lint-sh` を必ず入れ、ワーカーの返しの行と見張りをそろえる** (#4527): `contract.mjs generate --worktree` は、その worktree の `.commandmate/verify.yaml` が `lint-sh` を宣言していれば、生成する契約の `verify.gates` に必ず `lint-sh` を入れる（`lint` の直後。既定・書き出した gates・refactor の 2 ゲートのどれでも、足す向きだけ）。#4532 として、契約の goal は手番の最後の行を `DONE: #<N> <sha> verify exit <n>` / `WAIT: <理由>` / `STOP: <理由>` のどれかにし、`IMPL_COMPLETED` は形の外の終わり方（`SHAPE_OUTSIDE`。合格には数えない）にした。`orchestrate-monitor` は、セッションが動いていれば担当（Command Code・claude・codex ほか）を問わず毎ポーリング `capture --pane` を読み、終わり方をその全行で判定する（`capture --json` の `content` / `realtimeSnippet` は窓で、Command Code は top-anchored で余白に、codex は分割画面で下端の入力欄だけになるため。`--json` は状態・`promptData` に使う）。許可のプロンプトも、担当の既存の目印を pane にも当てて拾い（目印の無い codex はサーバーの `isPromptWaiting` に任せる）、`--pane` の読み取りに失敗したら担当ごとに 1 回 `WARN` を出す。返しの行・許可のプロンプト・新しいコミットの 3 つで鳴る。`DONE:` の形は wait-verify の `DONE_LINE_RE` を launch-worker と共有し、monitor の形も同じ意味（区切りは空白・タブの 1 つ以上、sha は 7〜40 桁の 16 進）にして、同じ表の行で一致を試験で固定した。`wait-verify` の timeout の文言も返しの行を名指す。
