- **chore(lint): `scripts/` の shell スクリプト 18 本に shellcheck を導入** (#2734): `npm run lint` は ESLint なので `.sh` を 1 本も読まず、`package.json` / `.github/workflows/` / `.commandmate/verify.yaml` のどこにも shellcheck が無かったため、サーバーの起動・停止（`stop.sh` / `stop-server.sh` / `start.sh`）と `.env` 読み込み（`load-env.sh`）が完全に無検査だった。`npm run lint:sh`（`shellcheck -x -P scripts --severity=style --exclude=SC2086,SC2317,SC2116 $(find scripts -name '*.sh')`）を追加し、CI の Lint ジョブに `npm run lint:sh` を走らせる専用ステップを 1 つ足した（`npm run lint` に `&&` で連結すると shellcheck の無い環境で `.commandmate/verify.yaml` の `lint` ゲートごと落ちるため独立スクリプトにしてある）。対象指定を `scripts/*.sh` ではなく `$(find scripts -name '*.sh')` にしているのは、直下の glob では `scripts/lib/port-pids.sh`（`stop.sh` / `status.sh` が source する `-sTCP:LISTEN` の PID 判定、#2473）を含むサブディレクトリの 3 本を取りこぼすため。`-x -P scripts` は source 先を追わせる設定で SC1091 の 12 件が消えるが抑止ではない。唯一の warning だった `scripts/load-env.sh:67` の SC2163（`export "$line"`）は理由コメント 1 行 ＋ `# shellcheck disable=SC2163` の 2 行で抑止した（ShellCheck は `# shellcheck <key>=<value>` しか解釈しないので ESLint の ` -- 理由` 記法を同じ行に書くと `SC1073` / `SC1072` で落ちる。ロジックは 1 文字も変更していない）。残る note 26 件（SC2086 23 / SC2317 2 / SC2116 1）は `--severity=warning` で丸ごと黙らせるのではなく 3 コードを名指しで除外して将来の info / style の指摘は拾えるようにし、修正自体は別 Issue に回した（SC2086 の `$PIDS` は単語分割されて個別の PID 引数になるのが意図であり、クォートすると停止処理が壊れるため本番の停止経路を bash 配列へ書き換える作業になる）。CI ステップは shellcheck を install せず `command -v shellcheck || exit 1` で fail-closed にしている（self-hosted 実機は 0.11.0 同梱、fork PR が落ちる `ubuntu-latest` イメージも同梱済み）。新規ガード `tests/unit/guards/lint-sh-scope.test.ts` が shellcheck を実行せずに設定側を固定する（`-x` / `-P scripts` / `--severity=style` を含み `--severity=warning` を含まないこと、`--exclude` 集合が 3 コードと完全一致、`scripts/*.sh` を含まず `find scripts -name '*.sh'` の形であること、`scripts.lint` に `shellcheck` が入らないこと、CI の当該ステップと job に `continue-on-error` が無いこと、そして「サブディレクトリに `.sh` が実在する」陽性対照）。
