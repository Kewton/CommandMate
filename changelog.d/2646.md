- **feat(app-update): 同梱リリースノート `release-notes/<X.Y.Z>.json` と `GET /api/app/release-notes` を追加** (#2646): 更新直後に出す「新機能と改善」（#2651）を UI の言語（ja / en）で出せるように、版ごとの利用者向け要約を日英のプレーンテキストで持つファイルをパッケージに同梱し（`package.json` の `files` へ `release-notes/` を追加。日本語のみの `CHANGELOG.md` はこれまでどおり同梱しない）、「ある版からある版までに入った変更」を返す API を足した。`src/lib/app-update/release-notes.ts` の `parseReleaseNote(raw, expectedVersion)` は版・日付・`{ ja, en }`・件数（各 30）・文字数（500）の規則を 1 か所で判定し、1 つでも反すればそのファイルごと捨てる（知らないキーは返り値に含めない）。`readReleaseNotesBetween(from, to, rootDir = process.cwd())` は `readdir` の結果のうち `^\d+\.\d+\.\d+\.json$` に合う通常ファイル（512 KiB 以下）だけを開き、`from < v <= to` を新しい順に最大 20 件返す（クエリの値でパスを組み立てないので traversal が届かない。ディレクトリとシンボリックリンクは `lstat` で除外）。「ノートが無い」と「読めなかった」は区別し、パスが無い（`ENOENT` / `ENOTDIR`）は `[]`、それ以外の I/O 例外（`EACCES` / `EIO`）は throw して route が 500 を返す。`GET /api/app/release-notes?from=&to=` はどちらかが `X.Y.Z` でなければ 400、`from >= to` はファイルを読まずに `{ notes: [] }`、全応答に `Cache-Control: no-store` を付け、認証は従来どおり middleware に任せる（`AUTH_EXCLUDED_PATHS` には入れない）。実際のノートファイルは #2652 の手順で次のリリースから作るため、`release-notes/` が無い間 API は常に `{ notes: [] }` を返す。同梱ファイルが実行時に黙って飛ばされることがないよう、名前・JSON・規則・版・シンボリックリンク・大きさの 6 種の陰性対照つきの検査（`tests/unit/release-notes/release-notes-files.test.ts`）を追加した。
