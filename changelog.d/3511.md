- **feat(ui): どの画面からでもエージェントへ依頼を送る「New task」ダイアログを追加** (#3511): `Mod+Shift+O`（Mac は ⌘⇧O、他は Ctrl+Shift+O。既存のショートカットと衝突しない）か、共通の開く関数 `openNewTask()`（`NewTaskContext`。サイドバー・アイコン列のボタンは #3512 が置く）で、一覧画面でも worktree 画面でも開く。送り先はリポジトリ → ブランチ → エージェントで選び、表示名ではなく **worktree ID＋instance ID** で持つ。既定は worktree 画面ならその worktree と選択中のエージェント、一覧画面なら最後に送った先で、最近の送り先 3 件をワンクリックで選べる（localStorage。読めない環境でも動く）。止まっているエージェントには「<agent> を起動して送ります」と先に出し、送ると既存の `POST /api/worktrees/[id]/send` が起動して届ける。モデル指定は send route と同じ条件で出し分ける（copilot は稼働中でも切り替え、claude・antigravity は起動時だけ＝稼働中・起動中は理由つきで無効、ほかのツールは対応していない旨を出す）。Auto-Yes は「この送信だけ」ではなく今の仕組み（instance に期間付き）のまま扱い、既に有効なら残り時間を出して変えず（期限を過ぎたら `AutoYesToggle` と同じ判定で無効扱いに戻す）、無効なら既定は「変えない」で、期間を選んだときだけ常に送る前に有効にする（有効化後に送信が失敗しても表示は有効のまま・再送で再び有効化しない）。409（プロンプト待ち）・400（モデル指定の拒否）・503（起動中／起動失敗）・送信失敗ではダイアログと依頼文を残したまま理由とサーバーの文を出し、送信中は ×・Esc・背景・`closeNewTask()` のどれでも閉じない（応答本文が届かなくても送信のタイムアウトで失敗にして閉じられる状態に戻る）。ほかのモーダル（`?` のヘルプ・設定・確認など）が開いている間は開かず、New task 表示中は `?` のヘルプも開かない（ターミナル内にインラインで出るプロンプトパネルや、最大化で隠れた分割の中身は「開いているモーダル」に数えない）。`⌘↵` / `Ctrl+↵` で送れ、送ったらそのブランチの画面へ `?instance=<送った instance>`（#2656 の経路）で移って送った instance を選んだ状態にし、トーストで送り先を出してクリックで元の画面へ戻る。`?` の一覧にも 2 つのキーを載せた。サーバー側の変更はない。
