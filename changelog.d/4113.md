- **docs(agent-roles): 各 CLI へロールを渡す方法を実機で確かめ、adapter 契約を確定** (#4113): `docs/design/agent-roles-adapters.md` に 7 adapter の渡し方・合成規則・再開時の扱い・失敗時の応答をまとめた（コードは未変更）。実 CLI の TUI を確定モデルへ向け、実際に送られる要求を記録して判定。Antigravity を除く 6 adapter について、確かめられた範囲で send・hook・approval・`wait --verify`・契約タスクの結果がロールの有無で一致した（V1 の `wait --verify` と契約タスク、V2 の approval は未確認）。主な結論は、**Codex の未知プロファイル・Command Code の欠落した mod・OpenCode の欠落した instructions は対照との画面の差が無いまま、Copilot TUI の未知 agent は `✗` を出して、ロールなしで動き続けるので起動前の検査が必須**、**OpenCode V2 は `OPENCODE_CONFIG_DIR` が大域設定を置換し `instructions` も効かないので、実効 agent の `system` を `OPENCODE_CONFIG_CONTENT` で上書きし利用者の env と合成する**、**再開時に Claude / Codex は旧ロールを保持する**。Antigravity は認証の複製が要るため注入以降を未確認とし、本物のモデルがロールに従うかも未確認。V2 の共通指示とあわせて判断を仰いでいる。#4112・#4114・#4115 の本文との食い違いを同じ文書に一覧にした。
