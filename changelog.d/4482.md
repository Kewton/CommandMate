- **chore(orchestrate): リーダーが直接流した verify を run 番号から run-log に記録する `run-log.mjs record-verify` を追加** (#4482): wait-verify はワーカーの合図を待つため、リーダーが `commandmatedev verify <wt>` を直接流した run は run-log に手で `verify=ok` と run 番号を書くしかなかった（Sprint 7 の A1〜D2）。`record-verify --run <id> --wt <worktree id> --worktree <path>` は `verify show <id> --json` を読み、run 番号・head・結果を写す: `passed` だけを `verify=ok`、`failed`・`error`・`cancelled`・`not_started` を `fail`、ゲートごとに `gates=<id>:<ok|skip|fail>`（読む人のための欄で、precheck・merge-pr のゲートの再利用には使われない）。`running`・`queued` の run は結果を決めずに exit 3 で断る。run は HEAD を持たないので、**head はその run が確かめた木と同じだと言えるときだけ書く（fail-closed）**: 未コミットの変更が無い（`dirtyPaths`）、HEAD のコミットも HEAD の reflog の最新の移動（`git log -g -1 --date=unix --format=%gd HEAD`）も run の開始より前、`--worktree` が `ls --json` の `--wt` の path と realpath で一致、のすべてを満たさなければ、または run の worktree・id・task の不一致・記録済み・読めない値があれば exit 4 で何も書かない。直の run には開始時の manifest が無いので **env は書かない（`env=none`、`.env.json` も無し）**。`env-manifest.mjs` の `verifyEnvState` は `env=none` を `same` と読まず、`env=` の無い行と同じ `unrecorded`（警告つき）と読む。`--task` は照合だけに使い run に task が無ければ書かない。wait-verify の記録の形と `append` / `status` は変えていない。
