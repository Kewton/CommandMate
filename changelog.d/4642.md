- **feat(orchestrate): 読み取り専用の Milestone の整合の検査 `milestone-check.mjs` と `flow.yaml` の `milestone` の節を追加** (#4642): `node scripts/orchestrate/milestone-check.mjs check|summary` が、GitHub Milestone とディスク上の作業（worktree・開いた PR・`--plan` の状態ファイル）を照合し、野良（M1）・残骸（M1b）・残留／未着手（M2）・閉じ忘れ／受け入れ待ち（M3）・前の Sprint の残り（M4）・Milestone の片付け（M5）・#4461 に記録の無い移動（M6）を 1 コマンドで出す。今の Milestone は `.commandmate/flow.yaml` の `milestone.current`（名前で書く。推さない）で、`roadmapIssue`（M6 の記録先）と `mergedWindowDays`（既定 14）は任意。exit は 0 ずれ無し／62 ずれあり／61 判定できない／2 使い方・設定の誤りで、強い順は 2 > 61 > 62 > 0。`check` は gh・git の失敗・時間切れ・`--limit` に当たって切れた・JSON が読めないのどれでも `complete: false` で 61（部分的な結果をずれ無しと読まない）、番号の取れない worktree と開いた PR は `keyless` に出して黙って落とさない。`summary --md` は `## Milestone <current>（<完了>/<全> 完了）` と固定の 5 見出し（完了／進行中／残り／先送り／ずれ）で Issue ごとの現在地（worktree・PR・plan）を出す。証拠の鍵が読んだどの一覧にも無いときは `gh issue view <N> --json number,state,milestone,labels` を 1 つの鍵に 1 回だけ（番号の順）で読み、CLOSED なら行を出さず OPEN ならその Milestone で M1・M1b を決める（閉じた Issue に残った worktree を野良と出さない）。`gh api --paginate` の続いた JSON の配列（`[…][…]`）は順に読んで 1 つにする。呼び出しは許可の表（`git worktree list`・`git rev-list --count origin/<base>..<branch>`・`gh api …/milestones`・`gh issue list`・`gh pr list`（open/merged）・`gh issue view`（コメント・鍵の状態）・M6 の timeline と roadmap のコメント）に限り、表の外は `refused` で呼ばない（読み取り専用・`fetch`/`http` を使わず本番 3000 も読まない）。`scripts/flow/config.mjs` は `milestone` の節を `wip` と同じ形で読み（`current` は必須、知らない鍵は exit 2）、節が無い flow.yaml の読みは今までどおり。実装の定義は `docs/design/milestone-check-4642.md`、exit の対応は `docs/orchestrate/exit-codes.md`。運用文書への組み込み（検査を流す時点・承認の後の同期の手順・PM の報告の固定ヘッダ）と画面・CLI の可視化は後続の PR・設計。
