- **feat(cli): `respond --expect-screen <kind> --observation <token>` — 観測した画面にだけ答える厳格モード** (#3756): `commandmate prompt` の観測トークンを付けて答えると、サーバが送る直前に取り直した画面で kind・トークン（pane・session 世代・画面の出現・選択肢・選択中の位置）・信頼の確認のフォルダ（`--expect-target`、省くと何も送らず画面のフォルダを返す）・答えの選択肢・画面が pane の最下部で開いていること（生成中の返答に引用された信頼の確認には答えない）を確かめ、どれかが合わなければ何も送らず exit 40 と観測した kind を返す。専用の `POST /api/worktrees/:id/prompt-response/strict` へ送り、endpoint の無い古いサーバでは止まる（照合の無い `/prompt-response` へ fallback しない）。答えるのは `antigravity-trust` と `antigravity-permission` だけで、番号の無い信頼の確認は画面に見えている選択肢の label の一意一致（`Yes` → `Yes, I trust this folder`）を ↑/↓ と Enter として送り、番号・`--default`・同名や複数に当たる label・画面外の選択肢は拒否する。キーは 1 つずつ送り、矢印の後に画面を取り直して同じ画面のまま選択が動いたことを確かめてから次を送る。送信を始めた後の部分送信・結果不確定は exit 41（再送してはいけない）、Enter の後は `outcome`（`advanced` / `next-prompt` / `unchanged` / `indeterminate`）を返し、成功は前の 2 つだけ。トークンは送る前に使い切り、同じ instance の厳格な送信はサーバ内で直列化、`--operation-id` が同じ再送は覚えている結果を返して二重に送らない。起動処理（#3757）の「Enter 1 回の借り」とは、厳格な送信の間は借りを取らせず、信頼の確認に答えたら借りを捨て、起動の窓が開いている間・借りが取られた直後は答えないことで二重に答えない。誰が・どの画面に・どの選択肢を送ったかを server.log（`strict-prompt-answered` / `strict-prompt-response-refused`）と task の履歴（`prompt_answered_human`）に残す。`--json` は stdout に結果オブジェクト 1 個。auto mode の許可を得る手段ではない。
