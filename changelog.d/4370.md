- **docs(design): マシンの資源の受付と配分の設計を追加** (#4370): `docs/design/resource-4370.md` を新設。CommandMate 全体の上限を `~/.commandmate/resource.yaml` の割合（`commandmate_share`）から全体の枠 S として決め、Docker の VM の割り当て・既存の `cpu.heavy` の予約・ホストの枠 C に分ける。ホストの枠は既存の machine-lock（`machine-lock-sync.mjs`）の短い受付のロックの中で保有者の記録を数えるセマフォとし、優先度 P0〜P3 は始める順だけ（詰め込みなし・走っているものは止めない）、1 分の load が上限を超えたら P2・P3 を止める門、死んだ持ち主の回収は #4288 の lease の規則（pid と世代、不明は回収しない）を流用し、保有者はグループと先頭の起動時刻で見る（`run` の子は呼び手のグループに残す）。最上位の不変条件（観測から決める・足すときだけ判定する・枠は最も内側で取り持ったまま他を待たない）を置き、判定に使う C は同じ受付の臨界区間で一覧した公開済みの参加者の設定上の容量の最小とし（`state.json` は写し、読めなければ受付を止める）、既定値はどの論理 CPU 数でも C ≥ 1。CI の待ちは枠の外。`cpu.heavy` を枠へ移す後の PR の条件（予約を外す条件・取る順 merge のロック→`cpu.heavy`→枠・待ち切れを合格にしない）も書いた。マシンで 1 つのランナーのコントローラー（合計の上限・launchd で常駐・5 分ごとの健康）、不変条件・状態と遷移・外部の呼び出しごとの失敗の倒れ方・PR の切り方（PR1〜PR7）・試験の表・人の操作と判断（Docker の自動の再起動は既定で通知だけ、E2E は GitHub のランナーへ試しに移す、別のリポジトリは CommandMate が起こす処理だけ通す）・他の子への約束、この run で実装する PR1a（設定の読み手・純関数・読み取りだけの `resource.mjs status`）の範囲・受入基準・試験の表・gates と、取得と `run` の PR1b の条件を書いた。P0 だけの予約は採らず人の判断へ。コードの変更は無い。
