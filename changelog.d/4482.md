- **chore(orchestrate): リーダーが直接流した verify を run 番号から run-log に env つきで記録する `run-log.mjs record-verify` を追加** (#4482): wait-verify はワーカーの合図を待つため、リーダーが `commandmatedev verify <wt>` を直接流した run は run-log に手で `verify=ok` と run 番号を書くしかなく、`env=` が残らなかった（Sprint 7 の A1〜D2）。`record-verify --run <id> --wt <worktree id> --worktree <path>` は `verify show <id> --json` を読み、run の事実だけを写す: `passed` だけを `verify=ok`、`failed`・`error`・`cancelled`・`not_started` を `fail`、ゲートごとに `gates=<id>:<ok|skip|fail>`。`running`・`queued` の run は結果を決めずに exit 3 で断り、run の worktree・id・task が違う、HEAD が run の開始より後のコミット（または `--head` と違う）、同じ work item に記録済みなら exit 4 で断る（何も書かない）。直の実行には開始時の manifest が無いので、env は**記録する時点の manifest**（note の `env-at=record`）とし、`env-manifest.mjs` の `manifestHash` で `env=<hash>` を書いて `verify-<work item>.run<id>.env.json` に置くので、precheck / publish / merge の `verifyEnvState` は wait-verify の行と同じに照合する。wait-verify の記録の形と `append` / `status` は変えていない。
