- **fix(send): 送信の途中で宛先が変わったら、その先の端末の操作を止め、409 `SEND_TARGET_CHANGED` と exit 34 で知らせる** (#4534): `send`・`ask`・relay の配送・`/terminal`・timer の 1 回の送信の間に宛先（worktree の行、instance の tool、OpenCode の dispatch 先）が変わった、または宛先を確かめる読みが失敗したら、その後のキー・貼り付け・起動・kill・`prompt_async` を打たずに止める（作成中の session は作り終える。自分が入れた本文の取り下げの消去だけは通す）。宛先が変わらない送信と送信の外の操作（Auto-Yes・respond・人の直接のキーなど）は今と同じ argv・回数のまま。止めた送信は `POST /api/worktrees/:id/send`（起動・copilot の `/model`・本文・dispatch）と `POST /api/worktrees/:id/terminal` が 409 `{ error, code: "SEND_TARGET_CHANGED", reason, target, current, requestId, sendOutcome }` で答える（`reason` は `worktree-gone`・`target-gone`・`tool-changed`・`dispatch-changed`・`unreadable`。`unreadable` は「確かめられなかった」で、変わったとは言わない。起動や消去の後で止めることがあるので、どの文も「何も入力していない」とは言わない）。`sendOutcome` は本文の入力も dispatch も始まる前に止めたときだけ `not_sent`、それ以外は `unknown`。CLI の `send`・`ask` は `not_sent` のときだけ **exit 34**（名簿を読み直して送り直せる。`--help` と `commandmate docs` の終了コードの表にも載る）で、`unknown` と `sendOutcome` の無い答えは今どおり exit 99（届いたかもしれないので先に pane を見る。結び付けた relay は取り下げない）。stdout には何も足さず、stderr は今の再送の注意の後に `Error: <サーバーの文>` を 1 行。`prompt --json` の `lastSend.reason` に `target-changed`（と呼び出しの誤りの `fence-misuse`）が加わり、timer の失敗の理由は `[target_changed]` で始まる。起動の途中で止めたときは起動失敗の通知を出さない。relay の予約の喪失（500・`code` 無し）・`PROMPT_WAITING`・`roster_changed`（exit 31）・`TOOL_POLICY_DENIED`（exit 33）の答えは変わらない。設計: `docs/design/send-fence-4534.md`。
