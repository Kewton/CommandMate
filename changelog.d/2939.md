- **fix(cli-tools): `opencode` が OpenCode V2 を指していても OpenCode（1.x）と OpenCode V2 を取り違えない** (#2939): npm `@opencode/cli`（V2）は `opencode2` と並んで `opencode` も登録するため、`PATH` の順だけで `opencode` が V2 になり、OpenCode（1.x）が「入っている」と判定されて V2 に `--port` / `--hostname` を渡して起動に失敗していた。判定を名前（`which opencode`）から `--version` の出力に変え、OpenCode は `PATH` 上の `opencode` のうち `1.x` を返すもの、OpenCode V2 は `opencode2`（無ければ `opencode v2.x` を返す `opencode`）だけを「入っている」とする。判定で見つけた実行ファイルの絶対パスを起動行に使う（サーバーとペインの `PATH` の食い違いでも別物を起動しない）。`opencode` が V2 しか指していないときの OpenCode の起動エラーには理由（`opencode` が OpenCode V2 であること）を出す。V2 を `opencode` の名前でしか入れていない場合は、`opencode2` を名前で呼ぶラッパーを使わず `--standalone` で起動する。`capture --json` / `commandmate status` の版表示も同じ判定に揃えた（V2 の `opencode v2.x` を OpenCode の版として読まない）。両者が共有する `~/.local/share/opencode/opencode.db` を V2 が作り替えたことで OpenCode（1.x）が `no such column` で起動できなかったときは、opencode のログ（起動時刻以降の行、末尾 256 KiB まで）から原因を読み取り、起動エラーとして「V2 との共有データの食い違い」と対処（V2 だけを使う／1.x のデータを分ける）を表示する。両方が入っている環境では More 画面の「Default agents for new branches」に注意を 1 行出す（ja/en）。`docs/user-guide/cli-setup-guide.md`（ja/en）に共存の注意と分け方を追記。
