- **feat(mem): 人が画面で mem の項目を見て、追加・編集・close する（同時編集の競合と古い差分を画面に出す）** (#4227): 新しい画面 `/repositories/:id/mem?branch=<name>[&worktree=<id>]`（Repositories の行の mem の設定の「項目を見る」から開く。PC とスマホで同じ画面）で、ブランチの mode とそれを決めたもの・種類ごとの一覧（作成者・所有の instance・版・条件の評価・古さ・記録済みの決定の「未反映」）・未配送の知らせと「引き取る」を出し、mode が `on` のブランチでだけ、そのブランチの作業木と roster の instance を選んで人が書く（作成者・更新者は `human`）。書き込みの入口は `src/lib/mem/service.ts` の `memWriteFromScreen` の 1 つ（`POST/PATCH /api/worktrees/:id/mem/screen/items[/:itemId[/close]]`、画面の印が無ければ route と service の両方で 403 `screen_only`、CLI に口は無い）で、A の 3 つの入口と同じ検査に加え、人は A の作成者の検査を通るので、書き込みの直前の同じ transaction で作業木・instance の寿命（`isSameInstanceLifetime`、正当な `null → lazy` は通す）・項目の所属のブランチ・要求のブランチ（`expectBranch`、HEAD が別のブランチへ移れば 409 `membership_changed`）・mode を照合し、違えば何も書かない。保存と close は読んだ版を送り、他で変わっていれば 409 `version_conflict` で画面が「自分の下書き・読んだときの値・今の値」を並べ、載せ直しは人が押したときだけ。画面はフォーカスの復帰と 30 秒ごとに読み直し、版が進んだ行に「更新されました」を付ける。反映しないと決めた `recorded` の decision は、2 段の確認の後でだけ新しい遷移 `withdraw-recorded`（`closed`・`withdrawn`）で閉じる（版の照合と close を 1 つの transaction に置く `closeMemItemVersioned`。確認が無ければ 409 `confirmation_required`、`commandmate mem close` は今どおり exit 55 で断る）。`now` はこの画面では書かない（#2427 のセッションのメモのまま）。mem の設定の画面は各 mode と機能の説明（「ポップアップ」は対話＝開始・終了の確認を画面に出す／無人＝既定、auto-yes とは別）を出し、項目の画面からその場で開いてブランチの上書きを足せる。不変条件（作り直し後の古い要求・`off`/`derived`・版の競合・所属・寿命・印）は A の `ENTRANCES` に `screen-add`・`screen-update`・`screen-close`・`screen-close-recorded` の 4 行を足して表で回し、書き込み関数の側から入口を数える検査と陽性の対照で固定した。終了の流れ（依頼・提案・承認と確定・停止の観測）と開くときの選択は後続の PR で足す。
