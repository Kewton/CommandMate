- **chore(verify): `unit-related` ゲートを「関係するテストとリポジトリを読むテストの和集合 1 回 × 最大 4 組の同時実行」に変更** (#4577): `node scripts/run-related-unit-tests.mjs --base <ref>` は、これまで vitest を 2 回（`--changed` / `related` の集合と、リポジトリのファイルを読むテスト）続けて起こしており、両方に入るファイル（実測 363 本）を 2 度流していた。今回から、関係するテストの集合を vitest の Node API（`getRelevantTestSpecifications`。`vitest run --changed` と `vitest related` が使うものと同じ）で先に取り出し、リポジトリを読むテストとの和集合を 1 回だけ流す。和集合は vitest の結果 cache（`node_modules/.vite/vitest/*/results.json`）に記録された所要をもとに、長いファイルから順にいちばん軽い組へ入れる方式（LPT）で最大 4 組に分ける。各組は `vitest run <files>` として同時に起こす（ゲートの `CI=true` のまま各組は直列。組ごとに `/tmp/cms…` の短い一時 `TMPDIR` を使い、終わったら消す）。cache が無い・壊れているときは落ちずに等しい重みで分けるので、cache は分け方にだけ効き、流すファイルには効かない。**流すテストの集合と合否の基準は変わらない**。exit 0 になるのは、全組が 0 で終わり、かつ各組の json の報告で数えた「実際に流したファイル」が渡したファイルとちょうど一致したときだけ。どれかの組が非 0・signal・起動の失敗・報告が無い・ファイルの過不足のいずれかなら 1、集合を取り出せなければ 2。報告の行が変わる: `related exit=… textscan exit=…` の代わりに、集合（`set related=… textscan=… overlap=… union=…`）・分け方（`split=lpt groups=… cache=…`）・組ごとの行（`group i/N files=… expected=… actual=… ran=… exit=…`）・落ちた試験（`failed <file> > <test>`）・`result exit=…` を出す。各組の vitest の出力は全組が終わった後に組の順で出し、stdout を吐き切ってから終わる（pipe で 64 KB を超えても要約の行が欠けない）。各組の vitest とその worker はスクリプトと同じプロセスグループにいるので、ゲートがグループへ送る SIGTERM・SIGKILL でまとめて止まる。スクリプトだけが SIGTERM・SIGINT を受けたときも、各組の vitest とその子孫へ SIGTERM を回して一時ディレクトリを消し、同じ signal で終わる（SIGKILL では一時ディレクトリは残る）。計測（#4534 PR-B 相当の変更、1626 ファイル）では、同じ変更の unit-related が 47〜56 分だったのに対し、`--shard` による 4 分割で約 20 分。LPT ではさらに縮む見込み。
