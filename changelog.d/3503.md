- **feat(chat): チャットと History の Markdown 表示で ```mermaid を図にする（ダークテーマ対応）** (#3503): 確定済みのチャットの回答・思考・ツールログ（`ChatMarkdownBody` の新しい `renderDiagrams`、渡すのは保存済みの行の `ChatMessageBubble` だけ）と History の会話カード（`AssistantMarkdown`）で、ファイルプレビュー（#100）と同じ `MermaidCodeBlock` を使って mermaid のコードブロックを図にする。判定と図の枠は 1 つ（`mermaid-block-utils` の `isMermaidPreChild` と `mermaid-markdown` の `MERMAID_MARKDOWN_COMPONENTS`）で、mermaid 以外のコード・インラインコードの描画は react-markdown の既定のまま。生成中（`ChatLiveTurnBubble`）と保留中の吹き出しは図にせずソースのまま出す。図の下には既定で閉じた「ソース」の折り畳みを置き、元のソースを文字として出す（構文エラーのときはエラー文と開いたソース。プレビューも同じ）。図は `<pre>` で包まず、コード用の暗い背景ではない図専用の背景（`.mermaid-figure`、ライト/ダークで切替）に置く。テーマはアプリのテーマ（next-themes の `resolvedTheme`）から `default` / `dark` を選び、mermaid の `secure` に `theme` / `themeVariables` / `themeCSS` / `darkMode` を足して、ソースの frontmatter や `%%{init}%%` のテーマ指定よりアプリのテーマを優先する（テーマ以外のソース側の設定は残る）。`initialize` と `render` は 1 本の順番待ちで直列にし、テーマが変わったときだけ `initialize` し直してから全部の図を描き直す（描き直し中も前の図を出したまま。持ち主が外れた待ちは列を塞がない）。`securityLevel: 'strict'` は維持し、`suppressErrorRendering: true` で構文エラー時に `document.body` へ一時 SVG を残さない。同じ内容の図が 2 つあってもノード・エッジの ID が衝突しないよう、描画後の SVG の ID を図ごとの接頭辞つきに付け替える（参照も追従）。履歴検索（チャット・History）は、図の SVG・読み込み中/エラーの文・「ソース」の見出しを数えず（`data-search-skip`）、原文の位置を畳んだソースの本文（`data-mermaid-source`）と、図の前後の本文の同じ出現位置へ対応させ、ヒットのあるソースを開いて強調する（`applyHistoryHighlights` の新しい `sourceText`）。引用の中の ```mermaid（先頭の `> **Thinking**` の節など）と、1〜3 個の空白で字下げしたフェンス・リストの項目を開くフェンス（Markdown の描画と同じく字下げ分を除いた本文で比べる）もフェンスとして扱い、チャットでは思考・ツールログの節を別の区画（`chatSearchSections` と `data-search-section`）として照合するので、引用の中の図と同じ本文の通常の図があっても、それぞれのヒットはそれぞれの図のソースを開いて強調する（対応が決まらないヒットは別の図に当てない）。図の描画が終わったとき・テーマ切替で描き直したときは強調を掛け直す。回答のコピーは今までどおり原文。画像を含む図・端末画面をそのまま写した行・印刷は対象外。
