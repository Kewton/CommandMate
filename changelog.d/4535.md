- **fix(send): OpenCode へ届いたか分からない送信の後に、キー入力も 2 回目の HTTP の送信もしない** (#4535): opencode のサーバーへの送信（`prompt_async`）が応答なし・204 以外の 2xx・読み戻しの不一致で「届いたか分からない」（`unknown`）に終わったあと、送信器がキー入力に切り替えて（添付画像の送信ではパスの文をもう一度 HTTP で送って）同じ依頼を二重に届けることがあった問題を修正。`unknown` の後は何も打たず何も送らずに送信を失敗にし、`lastSend` は `indeterminate`（新しい `reason` `dispatch-unknown`）、送信 API は 500・`sendOutcome: "unknown"`（CLI は exit 99）を返す（今まで fallback が成功すると 201・exit 0 だった。timer は `failed`、relay の配送は保留になる）。送り直す前に `commandmate capture <worktree-id> --pane` で確かめる。あわせて、5xx と 3xx の答えを「受け付けなかった」ではなく `unknown` と読み（作った後に落ちた場合を否定できないため）、読み戻しの 404 は 1 回目で決めずに 4 回の読み戻し（間の待ちは合わせて 350 ms、各回の上限 5 s）がすべて 404 のときだけ未送信と読む（途中で見つかれば届いた、404 と別の答えが混じれば `unknown`）。4xx・`200 text/html`（status 200 のときだけ。201・202 などほかの HTML の 2xx は `unknown`）の後と、未送信と確かめた後のキー入力・パスの文の送信は今までどおり。添付画像の送信が `unknown` に終わったときは、パスの文の fallback もその前の再起動もしない。送信の途中で宛先が替わったときは今までどおり 409 `SEND_TARGET_CHANGED`（答えの `reason` は柵が断った理由、`lastSend.reason` は `target-changed`）。
