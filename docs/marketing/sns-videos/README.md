# SNS 投稿用ショート動画

各20秒 / 1280x800 / h264 30fps。`.ja.mp4` と `.en.mp4` は UI ごと撮り分けた別テイクで、
テロップの言語と画面の言語は一致している。

- 動画: [`videos/`](./videos/)
- 絵コンテ（文言を変える唯一の場所）: [`storyboards/`](./storyboards/)
- 生成スキル: [`.claude/skills/demo-video`](../../../.claude/skills/demo-video/SKILL.md)

## 素材の出所

**すべて隔離環境で録画している。** 使い捨ての `cmdemo-app` seed リポジトリ、専用ポート、
`$HOME/.commandmate-demo/cm.db` を使い、開発機の本番インスタンス（127.0.0.1:3000）と
本番 `cm.db` には一切触れていない。画面に映るのは `feature/demo-dark-mode` /
`fix/demo-login-error` / `README.md` / `src` だけで、private リポジトリ名も個人パスも
ソースコードも含まれない。

これは [`website/assets/media/README.md`](../../../website/assets/media/README.md) が
「動画を戻すなら隔離環境で撮り直せ、`docs/images/` から再エンコードするな」と要求している
条件を満たす素材である。ただし **ランディングページの no-video ルールは維持している** —
LP へ載せるかどうかは Issue #1272 の判断を意図して見直す作業であり、この資産の追加とは別件。

`docs/images/` の `demo-desktop.mp4` / `demo-mobile.mp4` は個人環境で撮られた旧素材で、
README の GIF が参照しているために残っているだけ。**再利用しないこと。**

## ターゲット

**主**: Claude Code / Codex / Gemini CLI を毎日使っていて、複数タスクを同時に回そうとして
破綻している個人開発者・現役エンジニア。Node 22+ / git / tmux は既に持っている層。

**副**: 複数 Issue を並行させたい小規模チームのテックリード / AI 開発ツールをウォッチする OSS 層。

**対象外**: 非エンジニア、AI エージェント未使用者、クラウド SaaS 志向（本製品は 100% ローカル）。

訴求の軸は「AI に書かせること」ではなく **「同時に走らせた複数エージェントを見失わないこと」**。
前者は既にコモディティで差別化にならない。

## 10 本の訴求ポイント

| # | ファイル | 訴求 | 刺す痛み | 主役シーン(尺) |
|---|----------|------|---------|--------------|
| 1 | `cm-01-parallel-worktrees` | worktree ごとに1セッション、並列実行 | ターミナルのタブ地獄 | 送信→生成 (8s) |
| 2 | `cm-02-status-at-a-glance` | 実行中/待機中がひと目で | どれが止まっているか分からない | 一覧 (5s) |
| 3 | `cm-03-never-miss-waiting` | 承認待ちを取りこぼさない | 気づかず何時間も放置 | スマホ承認 (6s) |
| 4 | `cm-04-multi-agent` | エージェントをタブで切り替え | ツールごとに端末を分ける | スマホ (5s) |
| 5 | `cm-05-send-and-walk-away` | 送ったら離れていい | 張り付き監視 | 送信→生成 (8s) |
| 6 | `cm-06-approve-from-phone` | スマホからワンタップ承認 | 承認のため席へ戻る | スマホ承認 (6s) |
| 7 | `cm-07-completion-detected` | 完了を自動検知 | 「終わった？」を見に行く | 完了 (4s) |
| 8 | `cm-08-tmux-in-browser` | tmux を捨てずブラウザに載せる | 既存環境を壊したくない | 送信→生成 (8s) |
| 9 | `cm-09-files-beside-session` | ファイルツリーがセッションの隣 | 差分のために IDE を開く | 送信→生成 (8s) |
| 10 | `cm-10-local-and-npx` | 100% ローカル・npx 一発・MIT | クラウドに預けたくない | 一覧 (4s) |

### #1 だけ構成が違う

\#2〜#10 は「タイトルカード 3s → record 4本 → アウトロカード 2s」で、静止カードが計5秒ある。
\#1 はカードの尺が間延びして見えるという指摘を受け、**タイトルカードを廃止して問いかけを
1本目の操作映像の上に重ね、アウトロを1秒に縮めた**。結果、20秒中19秒が操作映像になる。

| | #1 | #2〜#10 |
|---|---|---|
| 冒頭の問いかけ | 操作映像の上のテロップ | 静止カード 3s |
| 操作映像の合計 | 19s | 15s |
| アウトロ | 1s | 2s |

トレードオフとして、テロップは1シーンに1本しか置けない（`render-overlays.ts` が
`telop-<sceneId>.<locale>.png` で書き出すため、同一シーンの2本目は上書きされる）。
つまりカードを削ると訴求メッセージが1本減る。#1 では「ブランチごとに独立実行」を落とし、
「ブランチごとに1セッション」に統合した。

## 制作上の前提

- **10 本は同一フッテージ＋訴求別のテロップ/尺配分**。`record-scenes.ts` が撮れるシーンは
  4本（一覧 / 送信→生成 / スマホ承認 / 完了）に固定され、`storyboard.ts` が全絵コンテに
  この4本を含めることを両方向で検証するため、シーン構成そのものは変えられない。
- **映像に出ていないことをテロップで主張していない**。製品としての事実主張（100% ローカル、
  MIT、npx 60秒）は文字だけのカードに置き、映像の上に重ねる帯は画面で起きていることだけを
  説明している。
- \#9 は「ファイルツリーがセッションの隣にある」までが実映像。**Markdown エディタでの編集
  操作は素材に含まれていない**。編集まで見せるには新規シーンの実装が要る。
- \#4 はエージェントタブ（Claude / Codex / Antigravity）が画面上部に映っているが、
  **タブを実際に切り替える操作は撮っていない**。10 本の中では映像の裏づけが最も弱い。

## 再生成

```bash
# 文言を変える（絵コンテが唯一の編集箇所）
$EDITOR docs/marketing/sns-videos/storyboards/01-parallel-worktrees.yaml

# 1 本だけ撮り直して差し替える
.claude/skills/demo-video/scripts/demo-video.sh \
  --storyboard docs/marketing/sns-videos/storyboards/01-parallel-worktrees.yaml \
  --out docs/marketing/sns-videos/videos
```

`demo-video.sh` は絵コンテごとに撮り直す。10 本すべてを作り直す場合、同じ4シーンを 20 回
撮ることになるので、素材をロケールごとに1回だけ撮って `render-overlays.ts` →
`storyboard.ts --format plan` → `compose.sh` を絵コンテごとに回すほうが速い。

絵コンテの尺は素材の実尺で頭打ちになる（超えた分は最終フレームの静止で埋まる）。
今回の実測: 一覧 4.1–5.2s / 送信→生成 15.4–18.5s / スマホ承認 5.9–6.0s / 完了 3.6s。
