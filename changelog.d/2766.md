- **feat(ui): PC の分割ペインに、検出に依存しない「直接入力」モードを追加** (#2766): 分割ペインの composer メタ行に［直接入力］トグル（`data-testid="direct-input-toggle"` / `aria-pressed`）を置き、ON の間 composer の直上に `DirectInputBar` を描く。バーの入力欄で打ったキーは `encodeKeyEvent`（#2764）で `DirectInputEvent` に変換され、`POST /api/worktrees/[id]/direct-input`（#2765）を通ってそのままエージェントの tmux ペインへ届く — `isSelectionListActive` / `isUnclassifiedActive` / `prompt.visible` のどれにもぶら下げないので、検出が読めなかった画面（2026-09-20 の Command Code Plan review は `ctrl+a` でしか承認できず、ブラウザからも CLI からも打つ手が無かった）でも `Ctrl+A` や `Esc` を送れる。新設の `useDirectInput` は**同時に飛ぶリクエストを常に 1 本に保ち**、送信中に来たキーをキューへ積んで前の応答が返ってから 1 リクエスト（`MAX_DIRECT_INPUT_EVENTS` 件まで）にまとめるので、数十 ms 間隔の `keydown` が HTTP の到着順で入れ替わらない（tmux には並べ直す手掛かりが無く、届いた順がエージェントの読んだ順になる）。失敗時はキューを捨てて固定文言を出す（古いキーを後から流さない）。`encodeKeyEvent` が `null` を返すキー — Cmd+C/V/R、F キー、IME の変換中キー — は `preventDefault` せずブラウザに残し、IME は `compositionend` で確定文字列だけを 1 回送る。ペースト は改行を `\r` に正規化し `MAX_DIRECT_INPUT_TEXT_LENGTH` ごとに分割。`worktreeId` / `cliToolId` / インスタンスが変わったとき、およびセッションが落ちたときはモードを閉じる（別のペインへ打ち込み続けない）。トグルは #2598 のメタ行 1 行予算（`ONE_LINE_META_ROW_PX`=24px）に収まる高さ（22px）で、メタ行のコンテナ幅が 420〜520px の帯では描かない — その幅ではキーボードヒント（195px）と Auto-Yes（ON で最大 236px）だけで行が埋まり、2 分割ペインと 2x2 グリッド（行 431px）で Auto-Yes が切れるため（実測は `tests/e2e/composer-two-row-2598.spec.ts` の `MEASURE-2598`）。420px 未満（ヒントが出ない 3・4 分割）と 520px 以上（1 分割）では描く。対象は PC の分割ペインのみで、スマホ・Sessions タイル・Auto-Yes の挙動は不変。
