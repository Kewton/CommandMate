- **feat(ui): どの画面からでもエージェントへ依頼を送る「New task」ダイアログを追加** (#3511): `Mod+Shift+O`（Mac は ⌘⇧O、他は Ctrl+Shift+O。既存のショートカットと衝突しない）か、共通の開く関数 `openNewTask()`（`NewTaskContext`。サイドバー・アイコン列のボタンは #3512 が置く）で、一覧画面でも worktree 画面でも開く。送り先はリポジトリ → ブランチ → エージェントで選び、表示名ではなく **worktree ID＋instance ID** で持つ。既定は worktree 画面ならその worktree と選択中のエージェント、一覧画面なら最後に送った先で、最近の送り先 3 件をワンクリックで選べる（localStorage。読めない環境でも動く）。止まっているエージェントには「<agent> を起動して送ります」と先に出し、送ると既存の `POST /api/worktrees/[id]/send` が起動して届ける。モデル指定は send route と同じ条件で出し分ける（copilot は稼働中でも切り替え、claude・antigravity は起動時だけ＝稼働中・起動中は理由つきで無効、ほかのツールは対応していない旨を出す）。Auto-Yes は「この送信だけ」ではなく今の仕組み（instance に期間付き）のまま扱い、既に有効なら残り時間を出して変えず、無効なら既定は「変えない」で、期間を選んだときだけ `commandmate send --auto-yes` と同じく送る前に有効にする。409（プロンプト待ち）・400（モデル指定の拒否）・503（起動中／起動失敗）・送信失敗ではダイアログと依頼文を残したまま理由とサーバーの文を出す。`⌘↵` / `Ctrl+↵` で送れ、送ったらそのブランチの画面へ `?instance=<送った instance>`（#2656 の経路）で移って送った instance を選んだ状態にし、トーストで送り先を出してクリックで元の画面へ戻る。`?` の一覧にも 2 つのキーを載せた。サーバー側の変更はない。
