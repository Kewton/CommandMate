- **feat(agent-roles): 全対象ツールの起動と Schedule にロールを適用する** (#4115): 解決したロールを 7 adapter の起動行へ渡す。起動行に入るのはパスと ID だけで本文は入らず、ロールなしなら起動行は今と同じバイト列。通常の起動もドライバ内の自動再起動も `BaseCLITool.startSession` の 1 つの入口で一度だけ解決し（`lib/session/role-launch`）、`AgentLaunchContext` に DB は持ち込まない。再起動待ち・同時起動の合流・条件つき送信はどれも**注入 fingerprint** で比べる（名前と継承元は入力に入れない。本文、adapter・wrapper の版、Codex の既存の `developer_instructions`、V2 の実効 agent は入れる）。別ロールを要求した同時起動は未送信のエラー（`SESSION_LAUNCH_ROLE_MISMATCH`）。**失敗時は止める:** 所属が曖昧（`membership-undetermined` は 1 度だけ判定し直す）、合成元が読めない（Codex の `config.toml` は `smol-toml` で読取りのみ）、不正な `OPENCODE_CONFIG_CONTENT`、実効 agent に利用者の `system` がある、生成物の書き込みや検査の失敗、Copilot の `✗` はいずれも本文を送らず `ROLE_LAUNCH_REFUSED` と `sendOutcome: not_sent` を返す（Antigravity は既定で無効、`CM_AGENT_ROLE_ANTIGRAVITY_ENABLED=1` で有効）。利用者の env と合成した値は起動行に書かず、0600 の一時ファイルから渡して起動後に消す。**適用状態:** 起動を確認できた世代にだけ `launched` を記録し、既存プロセスの再利用では変えない。確認の手段が無い Command Code とサーバー再起動の後は「不明」のままで、ロールなしとは別の状態。`GET .../instances/roles` が `effectiveNext.injectionFingerprint` と `restartPending` を返し、OpenCode V2 には「既定の指示の置き換え」（`replacesDefaultInstructions`）を載せる。**API:** `POST /send` に `role`（検証して保存してから起動。実入力の直前に世代と fingerprint を確かめ、不一致と証拠なしは `ROLE_CONDITION_UNMET`）、`expectedRole`、OpenCode V1 の `newConversation` を追加（V1 が別のロールの会話を続けるときは、既定の変更やドライバ内の再起動でも `roleResume` と `application.resumedAcrossRole` で伝える）。`POST /tasks` は起動後に設定が変わっていれば契約を作らず、`launch-worker` は起動メッセージの時点の世代と fingerprint が変わると契約を送らない（exit 44）。**Schedule** は呼び出し側でリポジトリ→システムの既定を継ぎ（primary の個別指定は継がない）、明示 `agent` を取り消さない。日次要約は継がず DB も開かない。agent-health の probe は `--role-file` で渡した試験用のロールだけを使い、条件を結果に記録する。
