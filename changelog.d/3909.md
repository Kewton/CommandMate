- **feat(verification): 検証の待ちと実行を人向けの表示と run の記録にも出す** (#3909): #3884 でゲートの `log_tail` 末尾に入った `[timing] queue= mutex= run=` を、`commandmate verify` / `wait --verify` の GATE 行（`GATE unit PASS (exit=0, 600.0s, queue=30.0s, mutex=120.0s, run=600.0s)`。`waited=` の代わりに出す）と `verify history` の人向けの行（行末の `timing: unit(queue=… mutex=… run=…)`）に出す。行の無いゲート（何も待たなかったもの・#3884 より前のサーバの run）と mutex 待ちの SKIP は今までの表示のまま。`/orchestrate` の `wait-verify.mjs` は最後の verify の GATE 行を合計して `verify` の記録の `queueSec` / `mutexSec` / `runSec` に渡し、`run-log.mjs status --json` の `stages.verify` で読める（どのゲートも出さなかった run には書かない）。あわせて、run の**最初の**実行枠の待ちも取り消せるようにした: 2 枠が長いゲートを実行している間に取り消した run は、そのどちらかが終わるまで `running` のまま取消し API が `requested`（202）を返していたが、すぐ `cancelled` で閉じる（ゲートの行は作らない。空いた枠は次に待つ run へ渡る）。standalone の `cmate-verify` の `verify-run.sh` は commandmate-skills と byte-identical の pin があるため `waited=` の形式のままとし、理由と揃え方を `docs/design/verification-config.md` §9.3.1 に書いた（§9.2.1 のロックを取る場所も precheck の追加後に合わせて直した）。
