- **feat(cli): 止まっている画面を機械で読める形で 1 回観測する `commandmate prompt <wt> --instance <id> [--json]` と観測トークンを追加** (#3755): `GET /api/worktrees/:id/current-output?observe=1` が同じ capture から `promptObservation`（`schemaVersion` 付き）を返し、`prompt` はそれを表示する。payload は解決済みの対象（instance・pane）、観測時刻、session 世代、画面の kind・観測トークン・質問・承認対象（信頼確認ならフォルダ）・選択肢・現在の選択、回答経路、Auto-Yes の有効状態と poller の状態。**kind は新しい共通の語彙**（`src/lib/prompt-observation/kinds.ts`: `antigravity-trust` / `antigravity-model-picker` / `antigravity-permission` / `antigravity-slash-menu` / `composer` / `none` / `unknown`）で、`promptData.type` や agy の `antigravity_selection_list`（信頼確認・picker・slash メニューをまとめる）とは混ぜない。agy の信頼確認・picker・slash メニューは新しい読み取り（`detection/tools/antigravity/screens.ts`）で区別し、番号付きの許可は既存の `dialog.ts` を使う。計測していない画面は `unknown`。**観測トークン**（`po1.<発行時刻>.<HMAC>`、120 秒、プロセスごとの鍵）は instance・session 世代・pane・画面の出現（サーバが instance ごとに覚える `appearedAt`。別の画面・composer・none を観測すると捨てる）・kind・質問・選択肢・承認対象・選択中の位置に結び付き、使い捨て。`unknown` と session 世代が判らないときは発行しない（`tokenWithheld` に理由）。検証の入口 `verifyObservationToken()` / `consumeObservationToken()` / `observationBindingOf()` を後続の厳格な `respond`（#3756）のために export した（この変更では `respond` は変えない）。観測と観測の間に消えて同じ文面で再び出た画面は同じ出現と見なす。観測が失敗しても `current-output` は `promptObservation` を付けずに従来の body を返す。**「答えなかった理由」は 2 項目に分けた**: poller の実際の記録（`pollerRecord`、画面との対応 `screenCorrelation` は記録が画面を名指ししないため `unknown` / `type-mismatch` / `no-prompt-on-screen` のどれか）と、契約の方針をいま当て直した結果（`contractEvaluation`、理由は `AutoYesSuppressionReason` の語のみ）。記録が無いことを「回答可能」とは扱わない。取得できたら確認が無くても exit 0、セッションが無いときは exit 21。`wait` は poll に `observe=1` を付け、exit 10 の payload に同じ `observation` を足す（exit code・待機・猶予・`autoYesSuppression` は不変、古いサーバでは付かない）。
