- **fix(lock): verify-run.sh が札を外すときに token を読み直し、判定と違う札を外しうる問題を修正** (#4560): bash のランナー（`verify-run.sh` の `lock_acquire_path` と先頭の待ち `lock_wait_head`）は、前の札を「外してよい」（pid が死んだ・再利用・期限切れ）と判定した後、外す時点で `lock_json_field … token` を読み直して `lock_mark_done` に渡していた。判定と外す間に同じ名前へ別の札が入る（GC の後の番号の再利用など）と、生きた待ち手の札を `done` にしていた。直した後は、`lock_ticket_retirable` が判定に使った 1 回の読みの token（`LTR_TOKEN`）をそのまま渡すので、入れ替わった札は外さない（TS・同期 JS は前から判定の読みの token を渡しており同じ形）。標準出力の答え（`gone` など）・ログの文言・入れ替わりの無いときの動きは変えていない。
