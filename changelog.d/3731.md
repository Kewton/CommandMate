- **fix(cli): `start --daemon` で起動したサーバーの出力を `logs/server.log` に残す** (#3731): `DaemonManager.start()` が `npm run start` を `stdio: 'ignore'` で spawn していたため、`start --daemon` とそれで再起動する `commandmate update` のサーバーは stdout / stderr がすべて `/dev/null` に捨てられ、docs が案内する `tail -f ~/.commandmate/logs/server.log` のファイルは存在しなかった。以後は設定ディレクトリの `logs/server.log`（`--issue <N>` の並列サーバーは `logs/server-<N>.log`。新設の `getServerLogPath()`）を `O_APPEND | O_NOFOLLOW`・0600 で開いて子の stdout / stderr に渡し（親は spawn 後に自分の記述子を閉じる）、起動ごとに区切り行を書く。起動時に 10MB 以上なら `scripts/build-and-start.sh` と同じく `.1`〜`.3` の 3 世代へ回す（`rotateServerLog()`。回した各世代も 0600 にし、`scripts/start.sh` の 0640 のファイルを回しても権限が緩まない。シンボリックリンクは回さず辿らない）。ログを開けないときは警告して従来どおり出力を捨て、サーバーの起動は止めない。`commandmate status` は稼働中と PID ファイルが古いままのサーバーに `Log:` 行でパスを出す（`--all` 側も同じ）。`CM_LOG_DIR` は使わない — サーバー自身が `.env` から読む会話ログの置き場所であり、このパスは spawn の前と `status` から .env 無しに決まる必要があるため。
