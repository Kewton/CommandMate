- **feat(session): 会話の境界の検出と、送信経路への session brief の口（brief は空の実装）** (#4274): claude・codex・command-code の会話の境界（新しい起動・`/clear` や codex の `/new` などの reset・別の会話への resume・自動の再起動）を新しい台帳 `session_brief_boundaries`（migration **v68**、#4222 の v67 と並行）に持ち、境界の後の最初の「付けてよい送信」に brief を本文の前に **1 回だけ**付ける口を `sendUserMessage` に作った。プロセスの世代と会話は分け、既存のプロセスへの再接続は境界にしない。境界は起動の経路（`beginAgentSession`）・`worktreeId` と `instanceId` の両方を載せたフックの `SessionStart`（headless の実行のフックは使わない）・CommandMate が打った reset のコマンド（その送信の入力のロックの中で開く）から観測する。「1 回」は DB の claim（取る区間はロックの中・`withMemTarget` の同期の区間で所属・mode・instance の寿命を照らす）で決め、同時の初回の送信・送信の拒否（`not_sent` は戻す）・結果不明（`unknown` は再送しない）・サーバーの再起動の後も守る。mode `off`・`injectOnStart` が無効・所属が決まらないときは付けない。brief と本文の合計が #2464 で確かめた 48 KiB・240 行（`src/config/send-verified-limits.ts` に移し CLI の `--help` と共有）を超えるときは brief を外し、**利用者の本文は削らない**。brief を受け取る口 `BriefProvider`（`build` / 同期の `reserve` / `settle`）を定義し、D1 は空を返す実装なので本番の送信の本文・記録・応答は変わらない（差分の試験で固定）。`commandmate send --no-brief`（その 1 回だけ付けない）・`--with-brief`（境界が無くても付ける）、API の `brief: 'skip' | 'force'` を追加。relay の配送・Schedule・ターミナル・回答・slash コマンドには付けない。Timer は既存の試験が引数を固定しているため D1 では既定（付けない）のまま。
