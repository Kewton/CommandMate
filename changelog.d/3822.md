- **fix(auto-yes): 実行契約の照会に失敗したとき Auto-Yes が無制約で答える問題を修正** (#3822): 契約の照会（`getDbInstance` / `getActiveTaskForInstance`）が throw すると `readPolicy` は「契約なし」と同じ null を返し、それを 5 秒キャッシュしていたため、`mode: off` や `denyPatterns` を持つ契約があっても一瞬の DB 失敗でその確認に答えていた。照会の失敗を「契約不明」（`AUTO_YES_POLICY_UNKNOWN`）として「契約なし（照会は成功し、タスクが無い）」と分け、答える経路 — ポーラーの step 4（`polling/auto-yes-poller-steps.ts`）・Enter フォールバックの契約判定（`auto-yes-poller.ts`）・`PermissionRequest` hook（`hooks/permission-decision-service.ts`）— は不明なら答えない（キーを送らない・hook は `allow` を返さず no-decision＝通常の承認ダイアログ）。理由は専用の語 **`policy-lookup-failed`**（`AutoYesSuppressionReason` に追加、`mode` は `null`）で `lastSuppression` と WARN に記録し、`commandmate wait` は「because the server could not read the execution contract (the database lookup failed), so Auto-Yes does not answer until it can; …」と表示する（"by contract policy" とは言わない）。失敗の結果はキャッシュせず次の tick で再照会するので、照会が戻れば次の tick から契約どおりに戻る（成功した結果は従来どおり 5 秒キャッシュ）。agy の受信窓を過ぎたダイアログを再判定する receipt-log（`polling/auto-yes-poller-receipt-log.ts`）も不明を不明のまま読むので、照会が失敗している間に `policy-lookup-failed` の記録を「契約なし」と読んで消すことはない（WARN の `hint` も照会の失敗を名指す）。表示のための照会（worktree 一覧の `blocked`・`GET /api/worktrees/:id/auto-yes` の `contractPolicy`・prompt-observation）は不明を「契約なし」と読んだままで、契約ありと偽っては表示しない。CLI の `lastSuppression` の写し（`src/cli/types/api-responses.ts`）はサーバーの記録と同じフィールドで、型のテストで固定した。契約の無い利用者は照会が成功する限り挙動不変。
