- **feat(verify): env-clean が `$HOME` 直下の無関係なエントリで不合格にならないよう、verify.yaml の `options.envCleanIgnoreHomeEntries` で名前ごとに除外できるようにする** (#2890): 2026-09-27 の `/orchestrate` run で、ワーカーのコマンドと結び付かない `.semgrep`（並行ワーカー 3 本すべてに出た）と `.commandagent`（別プロジェクトのツールが作った）が `home-entries` の `unattributed` な追加として 7 本中 5 本の検証を exit 20 にしていた。除外できるのは `VOLATILE_ENTRY_PATTERNS` の固定リストだけで、リポジトリごとに足す手段が無かった。`options.envCleanIgnoreHomeEntries`（文字列の配列、既定 `[]`、最大 32 件）を足し、`$HOME` 直下のエントリ名との**完全一致**（glob・正規表現なし。`.semgrep-x` は `.semgrep` に一致しない）で `home-entries` probe の追加・削除の両方を数えないようにした（`commandmate-entries` などほかの probe には効かない）。除外は比較の段階（`diffEnvSnapshots` の 4 つ目の引数 `{ ignoreHomeEntries }`）だけで、採取済みのベースラインは書き換えないので、後からリストに足した名前は既存 task にも効く。除外した項目は黙って消さず、レポートに `ignored (options.envCleanIgnoreHomeEntries): .semgrep` の 1 行で出す。配列でない・文字列でない要素・空文字・`/` や NUL を含む・`.` / `..`・33 件以上は `VerifyConfigError`（実行は `error` で終わり、無視して通すことはしない）。このリポジトリの verify.yaml への追加は含まない（未対応のサーバが未知キーで設定エラーにするため、マージ・再ビルド後に足す）。仕様は docs/design/task-contract.md §2.6。
