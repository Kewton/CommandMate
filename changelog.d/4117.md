- **feat(ui): 設定画面・追加ダイアログ・名簿でロールを管理し、適用状態を表示する** (#4117): 設定（PC の歯車の「全般」、スマホの `/more`）にロールの作成・編集・削除とシステムの既定を、リポジトリ画面の各行に「システムの既定を使う／なし／ロール」を追加。削除は 409 の参照を見せ、「設定を外して削除」でだけ進む。ヘッダーの「+」は `POST /api/worktrees/:id/instances/roles` でインスタンスとロールを一度に作り、保存に失敗してもダイアログを閉じない。既定の表示は同じ API の `toolDefaults` を読むだけで解決を画面に複製しない（`継承中: レビュー担当［システム］`、`継承中: なし［リポジトリで明示］`、所属が曖昧なら理由）。名簿ペインの「セッションのロール」（スマホも同じ）で既存のセッションと、名簿に行のない primary のロールを変えられる。分割ヘッダーは `起動時: レビュー担当／次回: PM／適用待ち`、`起動時: 不明` のように起動時と次回を分け、`restartPending` が言わない限り適用待ちと書かず、「適用済み」とは書かない。**名簿の競合**: `PATCH /api/worktrees/:id` に `expectedRosterRevision` を追加（不一致は書き込み前に 409、送らないクライアントは従来どおり。応答に `rosterRevision`）。`GET` にも `rosterRevision` を追加。画面の保存は必ずこの条件を添え（持っていなければ先に読む。読めなければ保存せず理由を出す）、409 なら読み直して組み立て直すので、別のタブやスマホで増えた行を古い名簿で消さない。ロールの編集は変更した項目だけを送り、別の画面の改名を戻さない。保存はできたが最新の状態を読み直せなかったときは失敗と分けて再読み込みを促す。応答が失われた書き込み（5xx・無応答・本文の期限切れ）は失敗にせず読み直して確かめ、作成済みなら成功と同じ流れ、無ければ再追加を許し、確かめられなければ再追加を止めるので、押し直しで同じセッションが 2 つできない。名簿の保存の本文にも期限を設け、止まった応答が後ろの操作を止めない。CLI の `instances` は条件なしのまま。
