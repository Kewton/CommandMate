- **docs(design): merge train（複数の PR を 1 回の CI で確かめてマージする）の設計を追加** (#4369): `docs/design/merge-train-4369.md` を新設。train は GitHub の squash を手元で再現した単一親の鎖（`git merge-tree --write-tree --merge-base`）として作り、merge-base がちょうど 1 個の形だけを扱う（0 個・複数・`merge=` の属性・gitlink は外すか拒否）。最初の PR（PR1）は train の作成・組み合わせの確認（全候補の precheck の条件の和、テストの削除の許可は移さない、依存が違えば push の前に拒否）・train の ref の push・CI の判定（一意の train ID に結んだ run・最新の attempt・status context まで読む）・報告までで、base・PR・Issue には書かない（緑の train の後のマージは従来の `merge-pr.mjs`）。マージの段（PR1b）は、GitHub が期待する base を固定できない問題と途中で止まったときの未検証の接頭辞の方針を人が決めてからとし、推奨は train の鎖を fast-forward の push で一度に公開する案。死んだ train の未確認の書込みの回復と、ruleset・strict・merge queue による適格性を PR1b の条件にした。赤のときの接頭辞の探索（PR2）は「原因」と断定せず、外した後の残りを必ず検証し直す。`ci-pr.yml` の push に `train/**` を足すのは PR で足せること、merge queue はこのリポジトリ（個人の持ち物）では使えない見込み（未確認）であること、不変条件・状態と遷移・失敗の倒れ方・試験の表（事前レビューの R01〜R24 を PR1／PR1b／PR2 へ割り当て）・人の判断の未決 10 件を記載。
