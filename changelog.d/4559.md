- **fix(lock): 死んだ保有者を判定した回復者が、次の保有者のロックを退かしうる窓を狭めた（読み直しの後に止まった場合の窓は残る。#4559 で追跡）** (#4559): マシンのロックの先頭の待ち手は、保有者が死んだと判定するとロックを自分の名前へ退かしてから token を確かめ、違えば戻していた。判定の後に「残りの待ち＋60 秒」より長く止まる（スリープ・SIGSTOP。#4288 の前提 P0 の 10 分の内）と、その間に札が外れて次の待ち手が取ったロックを古い判定のまま退かし、戻すまでの空いた名前に別の取り手が入ると保有者が 2 人になりえた。この版では退かす直前に owner を読み直し、判定した token と違えば（読めなければ）退かさない — 同期版（`machine-lock-sync.mjs` の取得・`releaseAsHead`・`recoverIfDead`）、非同期版（`machine-lock.ts` の取得）、bash（`verify-run.sh` の `lock_acquire_path`・`lock_release_as_head`・`lock_recover_only`）。これで判定と退かす操作の間の窓は狭まったが、**読み直しの後・退かす（mv）前に P0 の内で止まった場合は、同じ形で保有者が 2 人になりうる窓が残る**（#4559 は開いたままで、別の PR で閉じる）。読み直しが一時に失敗したときは退かさず、次の周で判定し直して回復し、読めなかった点・パス・errno を 1 回名指す（D6・`recoverIfDead` は名指しつきの `kept`）。読み直しの時点でロックが消えていたときの D6・`recoverIfDead` の結果は従来どおり `absent`。`recoverLock` / `lock_recover` そのものの契約（退かしてから確かめ、違えば戻す）は残る窓の備えとして残した。止まらないときの回復・取得の順とログは変えていない。`docs/design/machine-lock-owner-atomic-4288.md` の保証の文を、回復者に残る窓を明記する形に直した（前提 P0 は変えていない）。
