- **feat(ui): PC の分割ペインに、検出に依存しない「直接入力」モードを追加** (#2766): 分割ペインの composer 上段ツールバーの右端（中断ボタンの左）に［直接入力］トグル（`data-testid="direct-input-toggle"` / `aria-pressed`）を置き、ON の間 composer の直上に `DirectInputBar` を描く。バーの入力欄で打ったキーは `encodeKeyEvent`（#2764）で `DirectInputEvent` に変換され、`POST /api/worktrees/[id]/direct-input`（#2765）を通ってそのままエージェントの tmux ペインへ届く — `isSelectionListActive` / `isUnclassifiedActive` / `prompt.visible` のどれにもぶら下げないので、検出が読めなかった画面（2026-09-20 の Command Code Plan review は `ctrl+a` でしか承認できず、ブラウザからも CLI からも打つ手が無かった）でも `Ctrl+A` や `Esc` を送れる。新設の `useDirectInput` は**同時に飛ぶリクエストを常に 1 本に保ち**、送信中に来たキーをキューへ積んで前の応答が返ってから 1 リクエスト（`MAX_DIRECT_INPUT_EVENTS` 件まで）にまとめるので、数十 ms 間隔の `keydown` が HTTP の到着順で入れ替わらない（tmux には並べ直す手掛かりが無く、届いた順がエージェントの読んだ順になる）。失敗時はキューを捨てて固定文言を出す（古いキーを後から流さない）。`encodeKeyEvent` が `null` を返すキー — Cmd+C/V/R、F キー、IME の変換中キー — は `preventDefault` せずブラウザに残し、IME は `compositionend` で確定文字列だけを 1 回送る。ペースト は改行を `\r` に正規化し `MAX_DIRECT_INPUT_TEXT_LENGTH` ごとに分割。`worktreeId` / `cliToolId` / インスタンスが変わったとき、およびセッションが落ちたときはモードを閉じる（別のペインへ打ち込み続けない）。トグルは横スクロールしない右端グループに置くので、1 / 2 / 3 分割・2x2 グリッドのどのペインでも丸ごと描かれ（#2797）、composer 行が 520px 未満ではキーボードアイコンのみ（名前は `aria-label`）、520px 以上でラベル付きになる。対象は PC の分割ペインのみで、スマホ・Sessions タイル・Auto-Yes の挙動は不変。
