- **fix(auto-yes): 待ちの間に止めた・作り直した Auto-Yes の tick が、旧い世代のまま回答・再予約しないようにする** (#3706): Auto-Yes の poller は tick の冒頭で一度 `validatePollingContext` を見るだけで、capture・所有権確認・Enter fallback の再読・送信関数の中の待ち（ガードの画面読み・キーの間の待ち・Enter 前の待ち）の後に「まだ同じ世代か」を見ていなかった。そのため Auto-Yes を切った直後でも待ちの間に始まっていた tick が 1 回は回答を送り、in-flight の間に disable → enable すると旧 tick が `scheduleNextPoll` でキーから state を引き直して新しい poller の `timerId` を上書きし予約が 2 本残っていた。tick の冒頭で **世代**（`startAutoYesPolling` が作る poller state そのもの・`auto-yes-state` の許可オブジェクト・CLI セッションの epoch）を取り、キーで引き直さず同一性で照合する。capture の後・各待ちの後・再予約の時に照合し、外れた tick は何も変えずに終わる（自分の poller が今も現役のとき＝許可の更新・セッションの作り直しだけは鎖を絶やさないよう再予約する）。送信関数 `sendPromptAnswer` と `sendSpecialKeys` には省略可能な照合関数（`stillCurrent` / `shouldContinue`）を足し、偽になった時点で以降のキーを送らず `PromptAnswerAbortedError` / `SpecialKeysAbortedError` で止める（渡さない手動の送信・他の呼び手の振る舞いは不変）。途中で止めた送信は回答としても error としても数えず、送り終えた回答は監査行と task event を残したまま、poller の状態（重複判定・error count・最終応答時刻）は tick 自身の世代にだけ書き、セッションが作り直されていれば応答 poller の再開と画面配信をしない。
