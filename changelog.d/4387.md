- **feat(sessions): `/sessions` の絞り込み用に、全 instance のロールをまとめて返す `GET /api/sessions/roles` を追加** (#4387): 応答は `roleByWorktree`（worktree id → instance id → `{ kind: 'role', roleId, roleName, basis: 'launched' | 'setting' }` / `{ kind: 'none' }` / `{ kind: 'ambiguous' }`）。稼働中でこのサーバーが起動した世代の `launched` 記録がある instance は起動時のロール（`launched`。設定を変えた直後も変わらない）、それ以外は次の起動時のロール（`setting`）。引き継ぎ元の root が食い違う instance は `ambiguous` で、`none` と区別する。サーバー全体を 1 回で読み（instance の設定と `launched` 記録は 1 文ずつ、git は root と worktree のパスごとに 1 回、root にロールの設定が無ければ git を呼ばない）、設定ファイルは読まない。当初案の `GET /api/worktrees` への同梱は、実測（root 設定あり・100 worktree で `dbMs` 約 1.2ms に対し増分 約 144ms）が目安（20ms または 2 割）を超えたため見送り、`/api/worktrees` の応答は変えていない。読めなかったときは 200 で空の map と `rolesUnavailable: true` を返してログに残す。
