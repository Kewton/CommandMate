- **fix(codex): codex 0.157 の共有デーモン経由で hook のインスタンスが取り違えられる問題を直す** (#2874): codex 0.157 から TUI は既定でマシン共通の `codex app-server --managed-daemon` につながり、hook はデーモンのプロセス（最初に起動したインスタンスの環境変数）の中で動くため、別インスタンス・別 worktree の通知（返答・停止・許可確認）がすべて最初のインスタンスとして届いていた。hook を注入する codex の起動行に `-c features.daemon_auto_start=false`（`CODEX_EMBEDDED_MODE_ARGS`）を付け、codex を埋め込みモードで動かして hook が各セッション自身の環境で動くようにした（注入しない経路は従来どおり）。あわせて `/api/hooks/agent-event` は、codex の `user_prompt_submit` の通知先インスタンスの tmux セッションが無いとき `agent-event-instance-not-running` を warn で出す（応答は待たず、振り分け直しはしない）。既にデーモンにつながっている codex は取り違えたままなので、再ビルド後に codex のインスタンスを再起動すること。
