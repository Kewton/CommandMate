- **fix(verification): verify-run.sh の本体だけが kill -9 されると、まだ走っているゲートのロックを次の取得者が奪う問題を修正** (#4288): mutex 付きのゲートは、子を「合図を見て受け取りの印を作るまで exec しない」形で起こし、本体が owner を**ゲートのプロセスグループ G（`pgid`）付き・新しい token（`<T0>-g<G>`）**で tmp＋`mv` に書き直して読み直してから合図を出す。書き直し・G の確認・合図のどれかに失敗したらゲートを始めない（`GATE <id> FAIL exit=125`・stderr `machine-lock-handoff-failed <lock> stage=…`・retry しない）。見張りは受け取りの印から timeout を数え、解放は通常の終了・timeout・取消し・EXIT trap の全経路で **G が空（ESRCH）になってから**で、空にならない G は run の終わりまでロックを持ち続ける（`machine-lock-release-deferred`）。読み手（bash・`machine-lock.ts`・`machine-lock-sync.mjs`）は、戻しに失敗して残った `<name>.lock.gone-<token>-<serial>`（退避名の形のものだけ）を記録が生きている・読めない間は保有中と読み、列の先頭が戻す・記録が死んでから回収する・途中で止まった戻しを完了・回収する。取得・回収・解放の判断に使う全ての観測（`kill -0`・owner の読み・一覧・`mkdir`・`rename`）を「生きている／いない／不明」の 3 値の関数に通し、EPERM・EACCES・EIO・一覧の失敗は不明として取らない・消さない・解放しない。待ちは予算で終わり、何が不明だったか（観測点・パス・errno）を bash は stderr の `machine-lock-unknown`、TS・同期 JS は戻り値の `unknown` に出す。観測点の表は `docs/design/verify-lock-holder-group-4288.md` §2.8 で、試験が 3 実装のソースから観測点と生の呼び出しを集めて表と突き合わせる。札（ticket）の形と #4277 の規約は変えない。
