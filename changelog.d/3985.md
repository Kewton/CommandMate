- **feat(db): 未適用の migration がある DB は、最初の migration の前に検証済みの複製を作る** (#3985): `runMigrations` が版の読み取りと新しい DB の拒否（#1353）の後、未適用の migration が 1 本以上あるときだけ、DB と同じディレクトリの `db-backups/`（0700）に `VACUUM INTO` で複製を作る（WAL の確定済みでチェックポイント前の更新も含む一時点の複製。名前は `<DB 名>.v<元>-to-v<目標>.<UTC 時刻>.<短い ID>.sqlite`、0600、`.partial` で書いてから rename）。複製は読み取り専用で開いて `integrity_check` が `ok` で版が元の版と一致することを確かめ、確かめた後にだけ完了済みを 3 世代に刈る。複製・確認・rename のどれかが失敗したら migration を始めずに起動を止め、メッセージに置き場所・理由と `CM_DB_SKIP_MIGRATION_BACKUP=1`（複製を省いて起動する逃げ道。既定は省かない）を出す。最新の版の DB・新規の DB（版 0 で表が無い）・インメモリの DB では作らないので、テストの DB は複製を作らない。最初の migration は `BEGIN IMMEDIATE` で始め、その中で版が複製時から変わっていないことを確かめる（別プロセスの migration との競合、#1360）。旧ビルドは新しい版の DB を拒むため、アップデートを戻すときは複製も戻す。手順（サーバーを止めて複製を戻し `-wal`・`-shm` を消す。複製後の更新は失われる）をトラブルシューティング（ja / en）に追加。
