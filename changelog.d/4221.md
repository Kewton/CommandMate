- **feat(mem): 人だけが有効にできる mem の設定と、所有・版を持つ項目の置き場・CRUD の CLI を追加** (#4221): セッションをまたぐ作業の状態を型の付いた項目として持つ土台（Epic #4220 の子 A）。mode（`off` / `derived` / `on`、既定 `off`）は登録 repository ごとのブランチ名の規則（上から最初に当たった行、`*` は `/` を含まない・`**` は含む、`detached` の行）とブランチごとの上書きで決まり、**変えられるのは Repositories の画面の各行の「mem」だけ**（書き込みの API は画面だけが付ける `X-CommandMate-Client: screen` ＋ `Origin` の一致が無ければ 403 `screen_only`。宛先は `X-Forwarded-Host`／`X-Forwarded-Proto` → `Host`／接続の scheme で決める）。CLI は `commandmate mem now / add / update / close / list / mode / purge`（`mode` は読むだけ）で、書き込みは mode が `on` のブランチだけ（`off`・`derived` は exit 50 で何も保存しない）。終了コードは 50 disabled・51 version_conflict・52 対象不明・53 ambiguous・54 duplicate_key・55 not_owner/state_forbids・56 limit_exceeded（入力の不正は 2）。所属は #4114 の登録 root の解決を一般化して、worktree の HEAD（ブランチ・SHA・**common-dir**）を membership と同じ試行で観測し、同じ同期の区間で書く（同じ Git の root で設定が違う・git が答えない root がある・観測の間に変わり続けるなら書かずに 53）。項目は `repository_id`＋ブランチに付き worktree の削除を越えて残り、作成者は instance の世代（`(worktree, instance ID, ツール)` の組の寿命。要求を受けた時点で固定し、書く直前に照合）で決まるので、instance を消して同じ ID で作り直しても前の項目は引き継がない。`now` は #2427 のセッションメモと同じ行（D7）で、mem の行は画面のメモの経路でも mem の検査（長さ・秘密らしい文字列・制御文字）と版（`baseVersion`。枠ごとの版の数を `session_note_versions` に持ち、削除を越えて番号を繰り返さない）を通る。mem の行でないメモは `off`・`derived` では今までどおり。PC とスマホのメモの編集欄は 400・409 で入力と理由を残して開き直す。自由入力の欄で断った文字列はエラー・`--json`・ログに出さず、出口（list・`--json`・競合の応答）は新しい規則で読み直して当たった項目を withheld の形（自由入力の欄の鍵をすべて出さない）で出す。`close_when` は文法・kind ごとの許可表・保存の形（schema 1）までで、評価は #4222（`tests/fixtures/mem/close-when-v1.json` を共有。`worktree` 条件は保存した世代の存続で決め、改名は不成立）。DB は migration v66（`mem_*` の表・`session_note_versions`・`session_notes` の列の追加。既存のメモは `version=1` の mem でない行のまま）。同じ OS 権限のプロセスが DB や API を直接書き換えることは防がない（`docs/user-guide/cli-operations-guide.md` の「防げないこと」）。
