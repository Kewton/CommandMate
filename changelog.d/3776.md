- **fix(cli-tools): gemini と agy の起動時の信頼確認を、カーソルが安全な行にあるときだけ Enter で通し、Auto-Yes と二重に答えない** (#3776): 起動時の確認を宣言（質問文・押してよい行・カーソル行・キー）と純関数 `decideLaunchDialog` で読む共通部品 `src/lib/cli-tools/launch-dialog.ts` を追加し、gemini と antigravity の `waitForReady`（agy は #3757 の「次の send が借りの Enter を送る」経路も）をこれに乗せた。以前は質問文が画面にあるだけで Enter を送っていたので、カーソルが gemini の `3. Don't trust`（`trustedFolders.json` に永続）や agy の `No, exit`（agy が終了）にあってもそれを確定していた。安全な行（gemini は `1. Trust folder`、agy は `Yes, I trust this folder`）以外では送らず `launch-dialog-held` を、文言や描画が宣言と合わないときは `launch-dialog-unrecognized` を warn に残す（画面本文はログに出さない）。実機測定（gemini v0.62.0・私設 tmux socket・一時 HOME、2026-10-17）で、Auto-Yes の poller がこの確認を既定（＝カーソル行）の multiple choice と読んで `1`（カーソルが Don't trust なら `3`）を答えていたと分かったため、codex の起動ダイアログと同じ `agent-launch-dialog` で抑止する。抑止は起動処理の待ちの間（新しい `src/lib/cli-tools/launch-window.ts` の窓）だけで、窓の後に残った確認（Enter が届かなかった・自動更新などで遅れて出た）はカーソルが安全な行にあれば poller が既定を答える。確認とみなすのは質問文の下に宣言した選択肢の行が並ぶ画面だけで、答える prompt がその選択肢であるときに限る（返答中の引用や diff、別の許可画面は抑止しない）（信頼の確認の Enter の後の gemini は自分で再起動し、未サインインの HOME では認証方式の選択が出るので、二重の Enter はそこで既定を確定しうる）。あわせて `forgetAutoYesHold(key, since)` が別 episode の Auto-Yes hold を消さないようにした（`waiting-push-notifier` の hold 解除が次の episode の hold まで消し、通知が最大 1 hold 分遅れていた）。
