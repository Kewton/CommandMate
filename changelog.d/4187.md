- **feat(opencode-v2): イベントストリームが切れている間に終わったターンの返答を、再接続したときに履歴へ記録** (#4187): OpenCode V2 の返答は V2 のサーバーの記録（`GET /api/session/{id}/message`）から書き、画面の読み取りでは保存しないことを設計として確定した（画面の行は `oc-turn:<user メッセージ id>` の鍵を持てず、切断中のターンを後でサーバーから書くと同じターンが 2 行になるため）。そのうえで、切断の後に**再接続した**とき（成功した接続がそれ以前にもあった購読だけ。初回の接続・heartbeat では走らない）、pending の再生の後に 1 回、切れた時点で追っていた session を読み直す**回復の同期**を追加した。読み方は通常の同期（新しい側のページで `user` を見たら止まる）と違い、History に既にあるターンでは止まらず、上限（5 ページ・50 ターン）まで前のページへ戻る（書き込みの順・時計のずれに依らず、上限の中の未保存のターンを残さない。鍵と直列化で二重にならない）。warn `opencode-v2-history-recovery-truncated` は、上限に達し、かつ読んだ最も古いページに未保存のターンがあったとき（その先にも取りこぼしがありうるとき）だけ出し、長いだけで全部保存済みの文書では出さない。読めなかった session は 2・5・15 秒後に 3 回までやり直し、だめなら warn `opencode-v2-history-recovery-failed` で打ち切る。再生のフレームが別の session を名指ししても切れた session は回復の対象に残り、model の latch は購読が今追っている session の同期だけが行う（遅れて終わった前の session の同期が表示の model を戻さない）。鍵と直列化は通常の同期と共通なので、重なっても行と配信は 1 回。回復の読みの途中で同じ session がまた切れたときは、古い読みの成功で新しい切断の分を対象から外さない。`--standalone`・自分で終わった購読・CommandMate の再起動の間に終わった返答（再起動の後の通常の同期は最新の質問を含むページで止まるため、前のページの分）は記録されず、読めるのはターミナルの画面だけであることを docs に明記した。relay への完了の知らせ・切断で失った Stop に対する `wait`・その場の告知の表示・再起動の後の回復は扱わない。
