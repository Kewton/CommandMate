- **fix(db): WAL に残った更新を落とす旧 DB の移行と、別 worktree の片付けで不合格になる env-clean を修正** (#3993): (1) `migrateDbIfNeeded()` は旧い場所の DB を `fs.copyFileSync` で本体だけ複製していたため、WAL モードでまだ本体に書き戻されていない更新（`-wal` にだけある行）が `.bak` と新しい場所の両方から落ちていた。`-wal` が空でないときは #3985 の migration 前の複製と同じ `VACUUM INTO`（読み取り専用で開き、1 つの読み取りトランザクションで整合したスナップショットを一時名に書いてから rename）で複製する。`-wal` の無い DB は今までどおりバイト単位の複製。(2) 検証の `env-clean` は、隣のワーカーのセッションを殺す事故（#1624）を捕まえるために別 worktree の `mcbd-*` セッションの消失を常に違反に数えており、オーケストレーターが別の worktree を片付ける（`instances <wt> kill`）と走っている検証がすべて `- mcbd-…-<別の worktree> [other]` で不合格になっていた（2026-10-29、#3957 の run 2401〜2404）。`commandmate instances <wt> kill`（`remove --kill` を含む）が成功するたびに、止めた worktree・インスタンスと呼び出し元（cwd と tmux セッション）を `~/.commandmate/session-kills/<UTC 日付>.jsonl` に 1 行記録し（30 日で削除、`commandmate-entries` probe の対象外、`CM_SESSION_KILL_LEDGER_ROOT` で上書き可）、サーバー側も kill-session API（UI の停止ボタン、`origin: browser` ／それ以外の要求は呼び出し元不明の `http`）と `session-cleanup.ts` の片付け（sync・リポジトリ削除、`origin: server`）で止めたセッションを同じ ledger に書く。ゲートはタスクの計測窓の中にその worktree の kill の記録があり、呼び出し元の cwd も tmux セッションもタスクの worktree でないとき（UI とサーバーの片付けは常にワーカー以外）だけ、その消失を `removedExternal` に分けて `· - <name> [external] (not counted: kill-session for <wt> instance <id> at <時刻> from <cwd> in <session>, not this task)` と表示し不合格に数えない。ワーカー自身が同じコマンドで隣を止めた場合・呼び出し元が分からない記録・`tmux kill-session` / `kill-server` のように CommandMate を通らない停止・tmux サーバごと消えた場合は今までどおり違反。
