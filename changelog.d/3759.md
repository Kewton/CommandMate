- **feat(cli): 直近の send が「未送信／送信済み／不確定」のどれかを `prompt --json` の `lastSend` と send の失敗メッセージで示す** (#3759): 起動の窓が時間切れになって最初の message が届かなかったとき（#3746: `Antigravity prompt not ready`）、その message が未送信なのか送信済みなのか不確定なのかを示すものが無かった。`sendUserMessage` が (worktree, tool, instance) ごとに直近の試行の結末をプロセスのメモリ（globalThis、上限 1024 件）へ記録する新モジュール `src/lib/session/send-attempt-state.ts` を追加し、記録は `at`・`state`・`reason`・`messageDigest`（本文の SHA-256 の先頭 16 桁のみ。本文は保存しない）を持つ。`state` は `not-sent`（本文のキーを 1 つも打つ前に失敗: `prompt-not-ready` / `session-starting` / `prompt-waiting` / `foreign-session` / `model-switch-failed` / `composer-not-empty`）、`sent`（submit を確かめた）、`indeterminate`（一部を打った後に失敗、または結果を確かめられない: `body-not-landed` / `replaced-by-completion` / `submit-unconfirmed`、submit を確かめられず claude / codex の composer にまだ本文が見えるときは `composer-residue`、それ以外の未知の失敗は `send-error`）。未知の失敗を `not-sent` にしない（「分からない」を「再送してよい」と読ませない）。`commandmate prompt --json`（#3755）の payload に `lastSend: { at, state, reason }` を足し（記録が無ければ null、古いサーバでは項目なし。digest は公開しない）、人向けの表示にも `last send:` 行を出す。send ルートの 500 の失敗メッセージ（`prompt not ready` など）の末尾に `[send state: not-sent (prompt-not-ready): …]` を足す（同じ本文で、この要求の開始後に作られた記録のときだけ）。ルートが send サービスの前で断る試行（セッション起動の失敗・他サーバのセッション）も `not-sent` として記録する。**どの状態でも自動で再送しない**: 再送するのは利用者／監督のエージェントで、`indeterminate` のときは `capture --pane` で画面を確かめる前に再送しないよう docs（ja / en の cli-operations-guide）に書いた。記録は try/catch の内側で行い、記録できなくても send の結果（`SendUserMessageResult` の形を含む）は変わらない。
