- **fix(cli-tools): copilot を `--model` 付きで起動すると依頼本文が実行されない問題を修正** (#2623): `commandmate send <wt> "<本文>" --agent copilot --model <モデル>` で copilot 1.0.85 を起動すると、`/model` の後に送った本文が実行されず、`wait --instance copilot` は #1975 の 60 秒保留の後に `basis=scraper_ready` で完了していた。原因は、copilot が起動直後にフック・スキル・MCP サーバを読み込んでいる間（入力欄の下の行が ` ● Loading: …` の間。約 3〜4.5 秒）も入力欄を表示していたこと。`sendModelCommand` は入力欄の有無だけで切替完了と判断して 22ms で戻っていた。読み込み中に送った `/model` は読み込みが終わってから実行されるが、その後ろに送った本文は入力欄に残るか消え、`UserPromptSubmit` / `Stop` フックも発火しなかった。修正後の `sendModelCommand` は、ステータスバーが待機表示（`/ commands · ? help`）になってから `/model` を送り、copilot の応答行（`● Model changed from … to <id>` / `● Switched model to: <id>`）が新しく出るまで待つ。`✗ Model "<id>" is unsupported.` / `is unavailable.` が出た場合や 30 秒以内に応答が無い場合は、本文を送らずに copilot の文言を含めて送信失敗（`stage: 'model'`）として返す。実行中のターンに `/model` を送ると応答行を出さずに切り替わるため、ターンが終わるまで待ってから送る。`--model` なしの送信も、読み込み中は読み込みが終わるまで待つ（実行中のターンへの送信は従来どおりすぐ送る）。Issue で疑っていた `MCP Servers reloaded` は起動ごとに 1 回出る表示で、`/model` とは関係なかった。1.0.85 の実画面 19 枚を `tests/fixtures/copilot-model-switch-2623.ts` に追加した。
