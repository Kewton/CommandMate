- **fix(tmux): 別の CommandMate サーバが作った同名 tmux セッションを、表示・送信・停止・採用の対象から外す** (#2865): worktree ID はディレクトリ名から作られるため、DB もパスも別の 2 台のサーバが既定ソケット上で同じ `mcbd-<cli>-<worktreeId>` を解決し、片方の画面に他方のセッションが映り、送信・キー入力・停止・Auto-Yes の応答・起動時の rename まで他方のエージェントに届いていた。セッションの `#{session_path}` の realpath が worktree の path の realpath と一致するものだけを自分のものとし（新規 `src/lib/tmux/session-ownership.ts`。path が取れないセッションも安全側で他サーバ扱い）、一致しないセッションはサイドバー・状態表示では稼働扱いにせず、`/api/worktrees/:id/*` の送信・キャプチャ・キー入力・応答・中断・停止・タイマー登録は HTTP 409（`code: 'session_owned_by_other_server'`・`sessionName`・`sessionPath`）で拒否し、`kill-session` の複数対象では自分のものだけ停止して `skippedForeignSessions` を返す。既存セッションの採用（全 8 ツール）は `ForeignSessionError`、WebSocket のターミナル購読は `terminal_error`、Auto-Yes は応答せず warn、タイマー発火とリレー配送が通る `sendUserMessage` は送信も応答ポーリング開始もせず `stage: 'foreign_session'` を返し（worktree 行が無く所有を確認できない場合も同じ）、起動時 rename は `skippedSessions` に記録、worktree 削除時の停止は kill しない。`tmux list-sessions` は `#{session_path}` をタブ区切りの最終列で返すようになった。セッション名の変更（名前空間）は #2866 で行うため、同名が埋まっている worktree では自サーバ側のセッションを起動できない（409）。
