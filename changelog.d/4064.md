- **fix(relay): 送信結果が不確定な relay の配送を自動で再送しない（二重提出の防止）** (#4064): relay（`ask --async` / `send --reply-to`）の返答・確認の通知・期限切れの通知の配送は、`sendUserMessage` の失敗を `prompt_waiting` 以外すべて `failed` にして pending を残していたため、`indeterminate`（`prompt-unreported`・`submit-unconfirmed`・`send-error`・`composer-residue`）でも、`sent` を確かめた後の例外（履歴の保存など）でも、次の pump が同じ payload を依頼元へもう一度打ち込みえた。配送は最初のキーより前に台帳へ `attempting` を永続で書き（v63 `delivery_state` / `delivery_attempt_id` / `delivery_owner` / `delivery_reason` / `delivery_at`）、その書き込みに成功した処理だけが送る（書けなければ送らない）。結末は送信自身の `onAttempt` で決め、`not-sent` は今どおり再配送、`prompt_waiting` は今どおり held、それ以外（`indeterminate`・`sent` 後の例外 `threw-after-sent`・状態の分かる前の例外 `send-threw`）は `uncertain` として payloadId 単位で保留し、配送の一覧（`listDeliverableRelayPayloads` / `listRelaysWithPendingPayload`）から外す。結果の更新は relayId・payloadId・試行 ID の一致が条件。再起動時に別の起動の `attempting` は `uncertain`（`server-restarted`）へ倒す（送信直前に止まった未送信も保留になる。安全側）。不確定な prompt 通知は、失敗時の finally・`stashReply` の直接置換・第 2 スロットの昇格・復旧のどの経路でも消さず置き換えず、その relay の後続の配送（第 2 スロットの返答を含む）を止める（ほかの relay は進む）。期限切れ・取消は以後の配送を止めるだけで、保留の本文・payloadId・理由は消さない（保留中に期限が来た relay には期限切れの通知を配送しない）。保留は `SessionRelay.deliveryHold`（`state` / `payloadId` / `kind` / `reason` / `at` / `checkCommand` = 依頼元の正確なインスタンスの `commandmate capture <wt> --instance <id> --pane`）として `GET /api/relays/:id` と `GET /api/relays` の `held`（閉じた relay も）で読め、`commandmate relays` は `# delivery not confirmed, not resent` の節と `delivery=` / `payload=` / `reason=` / `check=` を出す。既存の pending と NULL の payloadId は通常の queued のまま（NULL の payloadId は試行の取得時に付与）。日英の手引き（cli-operations-guide の relay の節）に「不確定な配送は自動で再送しない」を追記。
