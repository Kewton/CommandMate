- **docs(design): merge train（複数の PR を 1 回の CI で確かめてマージする）の設計を追加** (#4369): `docs/design/merge-train-4369.md` を新設。train は GitHub の squash を手元で再現した単一親の鎖（`git merge-tree --write-tree --merge-base`）として作り、CI はその先端の tree を 1 回だけ確かめる。各 PR は train の順に `gh pr merge --squash --match-head-commit` でマージし、送る前に base の先端が 1 つ前の自分の squash であること、送った後に base の tree が train の対応するコミットの tree と一致することを機械で確かめ、外れたら残りを送らない。`merge-pr.mjs` の確認（取り込み・衝突の印・precheck・`judgeChecks`・再実行・CI 待ちの base の移動・merge のロック・未解決の記録）を train のどの段で行うかを表にし、弱くなる点（途中の base は CI を通らない）も明記。赤は接頭辞の二分探索（PR2）、`ci-pr.yml` の push に `train/**` を足すのは PR で足せること、GitHub の merge queue はこのリポジトリ（個人の持ち物）では使えない見込み（未確認）であること、不変条件・状態と遷移・失敗の倒れ方・試験の表・PR1 の範囲（変更ファイル・受入基準・gates）・人の判断の未決 7 件を記載。
