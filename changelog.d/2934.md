- **feat(cli-tools): OpenCode V2（`opencode-v2`）をエージェントとして登録し、自前 serve と TUI を 1 ペインで起動・終了、SSE で状態を表示する** (#2934): Epic #2370 Phase 1。OpenCode 2.0（実行ファイル `opencode2`、npm `@opencode/cli`、検証済み 2.0.18）を v1（`opencode`）とは別のツール ID `opencode-v2`（表示名 `OpenCode V2`）として追加（v1 の実装・テスト・fixture・挙動は不変）。起動は新しいラッパー `scripts/opencode-v2/launch.sh`（bash 3.2 互換）で、`opencode2 serve --hostname 127.0.0.1 --port <N>` を立てて `GET /openapi.json` の 200 を最大 15 秒待ち、TUI（`opencode2 --server <url> <worktree>`）を動かし、`trap` で EXIT / HUP / INT / TERM のどれでも serve を止めるので `/exit`・TUI の終了・`tmux kill-session` のいずれでもポートが空く。ポートは v1（4200–4299）と重ならない 4300–4399、状態は `~/.commandmate/opencode-v2/`（ディレクトリ 0700）の `ports.json` とインスタンスごとのパスワードファイル `<複合キー>.pw`（0600、起動ごとに 32 バイトの乱数を生成）。パスワードは環境変数 `OPENCODE_SERVER_PASSWORD` にだけ渡し、起動行（`AgentLaunchPlan.env` / `command`）・tmux の画面・ログには出さない。状態は自前サーバの SSE（`GET /api/event`、Basic 認証）を購読し、`session.execution.started` → running、`succeeded` / `failed` / `interrupted` → ready（`failed` はエラーとして記録）、`permission.asked` / `form.created` → waiting、`permission.replied` / `form.replied` / `form.cancelled` → waiting 解除で表示する（1 インスタンス = 1 サーバなので `location.directory` の無いイベントも同じインスタンスに振り分ける）。CommandMate の起動時に、tmux セッションが生きているインスタンスは保存したポートとパスワードファイルから購読し直し、生きていないインスタンスのパスワードファイルとポートの記録は消す（起動後にペインを調べた時点でも購読し直す）。`launch.sh` は npm パッケージに同梱される（`files` に `scripts/opencode-v2/`）。送信は TUI の入力欄へ tmux 経由（入力欄の `┃  Ask anything…` か footer の `ctrl+p commands` を確認してから）。Schedule（CMATE.md）の CLI Tool には未対応で、検証エラーになる。承認・質問への回答・History は Phase 2、画面検出の充実・クイックキーは Phase 3。
