- **feat(auto-yes): Auto-Yes の判断・送信・解消と停止の区間を確認ごとに記録し、agent-health の日次で集計する** (#3820): サーバーが Auto-Yes の確認 1 件ごとに、判断（答える／止める・根拠の段 L1 / L3 / L4 / `enter-fallback` / `browser` / `human`・止めた理由）、送信の試行（`ok` / `partial` / `no-keys-sent` / `failed`。確認が閉じた後に戻った結果は `late`）、解消と停止の区間を構造化ログ `auto-yes-confirmation-*` / `auto-yes-withhold-*` / `auto-yes-hook-request-*` に出すようにした（新モジュール `src/lib/polling/auto-yes-confirmation-ledger.ts`）。経路は画面（poller）・hook・API（opencode）・`/prompt-response`。確認の識別は本文を残すキーで、本文が違えば別の確認に数え、agy の受信窓の外や Auto-Yes の OFF→ON をまたいでも同じ確認として続ける。1 時間ごとに生存の行と復元できる checkpoint を出す。agent-health の日次の計測に観測だけの指標 `auto-yes-observation`（category `process`。Issue は立てない）を足し、窓の中の停止の時間（分）・ツール別・根拠の段別の回答数・理由別の停止の件数と時間を出す（計測区間が無い日は skip。公開に載せるのは件数・時間・ツール名・語彙だけ）。**答え方は変えない**（記録とロガーの例外は回答・hook の返事・`/prompt-response` の応答に影響しない）。**利用者に見える履歴の変化: agy（antigravity）・command-code・gemini の hook の allow で、履歴に「Auto-Yes が許可した」行（`PermissionRequest allow · tool=…`）を書かなくなった** — これらは allow の後も確認を出すため、画面の回答の行と同じ承認を二重に書いていた。claude / codex / copilot / opencode は今までどおり書く。ソースの能力に `permissionAllowSuppressesDialog` を足し、CLI の `capture --json` の型と説明に載せた。設計は `docs/design/auto-yes-measurement-3820.md`。
