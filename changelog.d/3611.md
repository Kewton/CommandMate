- **fix(ui): 上の層が処理した Esc で、下のパンくず・タブ列の一覧・表示項目の設定・吹き出しまで閉じる問題を修正** (#3611): `Tooltip`・`FileMetadataToggle`・`WorktreeBreadcrumb`（ブランチの ▾ 一覧）・`RepositoryTabBar`（タブ列の一覧）の document / window の Esc 受けが、上の層（メニュー・見出しの「…」一覧など）が `preventDefault` 済み（`defaultPrevented`）かを見ていなかったため、1 回の Esc で上下の層がまとめて閉じ、フォーカスも下の層のボタンへ移っていた。判定を新設の `src/lib/escape-key.ts` の `isUnhandledEscape()` 1 か所に置き、4 部品とも「処理済みの Esc は無視する」にそろえた（#3591 の `ActionBarItemsOverflow`・#3592 の `VerificationStatusChip` と同じ動き）。`Tooltip` は WAI-ARIA の「Esc はまず吹き出しだけを消す」（`preventDefault` で Esc を奪う）は採らず、処理済みの Esc を無視するだけにした — ホバーで偶然出ている吹き出しが Esc を奪うと、モーダルやメニューを閉じるのに 2 回押す必要が出るうえ、`defaultPrevented` を見ない既存の Esc 受けが多く、#2319 の「利用側の Esc 処理を妨げない」という約束も崩れるため。吹き出しは `window` の bubble 段で受けるので、document の層（capture・bubble とも）が常に先に処理する順序をテストで固定した。
