- **fix(config): 相対の `CODEX_HOME` / `XDG_CONFIG_HOME` で、サーバーが書いた・読んだ設定とエージェントが読む設定が別の場所になる問題を修正** (#4233): 相対の `CODEX_HOME` は、サーバーが `hooks.json`・relay・ロールのプロファイルをサーバーの cwd（daemon では package root）に書く一方、codex は worktree の cwd で同じ文字列を解決するため、hooks もロールも届かなかった。`getCodexHome()` を `resolveSafeAbsoluteDirectory()` に替え、サーバーの cwd で絶対化した home を起動環境の `CODEX_HOME`・`hooks.json` の relay のパス・ロールの `CODEX_HOME` に渡す（#4191・#4210 と同じ向き。実体の場所は変わらない）。hooks なしの起動（`CM_AGENT_HOOKS_INJECT=0` など、ロールなし）は従来どおり起動環境に何も足さない。版の読み手（`updates/codex-version.ts`）は CLI の任意の cwd からも呼ばれるので、相対値では従来どおり「不明」と答える（#2069）。OpenCode V2 のロール判定は、相対の `XDG_CONFIG_HOME`（未設定なら `HOME`）をサーバーの cwd ではなく opencode の起動 cwd（新規 pane・Schedule は worktree）で解決して global 設定を読み、既存の pane へ送り直すときに pane の今の cwd（`#{pane_current_path}`）が worktree と違えば、推測せずロールつきの起動を拒否する（絶対値・未設定では cwd を読まない）。**移行の注意**: 相対の `CODEX_HOME` を使っている場合、切り替わるのは新しいビルドのサーバーが次に codex を起動したとき（稼働中の codex の pane は終了して起動し直すまで旧い相対の home のまま）。relay のパスが変わるので `hooks.json` の再信頼（`Modified since last trusted`）が 1 回だけ出る（既定・絶対値の利用者には出ない）。相対の `CODEX_HOME` で起動された codex が worktree の下に作った `auth.json`・履歴などは自動では移さない。旧版のサーバーと同じ cwd で併走させるなら `CODEX_HOME` を絶対パスにする。あわせて `docs/design/child-process-env-scope-1996.md` と `env-sanitizer.ts` の説明を今の宣言（`AGENT_LAUNCH_CONDITIONAL_CONFIG_ENV_VARS`）に合わせ、当時の実測の記録と分けて書いた。
