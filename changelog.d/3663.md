- **fix(polling): worktree ID の一括移行で、保留中の取り込みも新しい ID へ移す** (#3663): `migrateResponsePollerWorktreeIds` は poller と dedup の状態を新しい ID へ移していたが、#2436 の保留中の取り込み（`__pendingScrapedResponses`）は古い poller キーに残していた。再起動した poller は新しいキーで期限切れを確かめるので保留は二度と見つからず、保留していた返答が書かれないおそれがあった。dedup と同じ形（#3553: すべての移送元を先に退避してから移送先へ書く）で、走っている poller と prompt で一時停止中の chain の保留を一緒に移し、保留の `worktreeId` を新しい ID に書き換える（期限と本文はそのまま）。入れ替え（A↔B）・連鎖（A→B→C）でも失われず混ざらない。移送先に既に保留があれば、移ってきた response hash と対になる移送元の保留で置き換え、置き換えた保留は `poller:migrate-pending-scrape-replaced` で warn ログに残す。保留の map は poller から読み込める軽いモジュール `pending-scraped-response-store.ts` へ分けた。保留が無いときと、単独の `renameResponseHashCacheKey` の振る舞いは変わらない。
