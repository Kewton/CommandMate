- **fix(tmux): 新しいセッションの起動で、ペインのシェルが起動コマンドを約 61 秒実行せず送信が exit 99 になることがある問題を修正** (#2958): 原因は `createSession` が `new-session` で作ったウィンドウ 0 のログインシェルを、数ミリ秒後の `new-window -k`（Issue #1624 の history-limit 反映のための作り直し）で殺していたこと。rc ファイルの途中で殺されたシェルは pyenv の `pyenv init -`（`command pyenv rehash`）のロックファイル `$PYENV_ROOT/shims/.pyenv-shim` を残すことがあり、作り直した側のシェルが `pyenv rehash` のロック待ち（既定 60 秒）で止まり、CommandMate の起動待ち（60 秒）に間に合わなかった（ペインには `pyenv: cannot rehash: … exists` が出る。タイムアウトした rehash が終了時にロックを消すので次の起動は速い）。tmux 3.5a / pyenv 2.6.0 の隔離ソケットで、従来の手順は 40 回中 7 回ロックを残し、次のシェルの最初のコマンドが 61 秒後に実行された。ウィンドウ 0 をシェルではなくプレースホルダー（`sleep 2147483647`、2 語なので tmux がシェルを介さず直接 exec）で作るようにし、同じ手順で 40 回中 0 回になった。作り直しに失敗したときは、プレースホルダーのままにせず `default-shell` をログインシェルとして `respawn-pane -k` で入れ直す（それも失敗したらセッション作成の失敗として返す）。
