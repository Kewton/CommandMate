- **feat(auto-yes): Auto-Yes の判断・送信・解消と停止の区間を確認ごとに記録し、agent-health の日次で集計する** (#3820): サーバーが Auto-Yes の確認 1 件ごとに、判断（答える／止める・根拠の段 L1 / L3 / L4 / `enter-fallback` / `browser` / `human`・止めた理由）、送信の試行（`ok` / `partial` / `no-keys-sent` / `failed`。確認が閉じた後に戻った結果は `late`）、解消と停止の区間を構造化ログ `auto-yes-confirmation-*` / `auto-yes-withhold-*` / `auto-yes-hook-request-*` に出すようにした（新モジュール `src/lib/polling/auto-yes-confirmation-ledger.ts`）。経路は画面（poller）・hook・API（opencode）・`/prompt-response`。確認の識別は本文を残すキーで、本文が違えば別の確認に数え、agy の受信窓の外や Auto-Yes の OFF→ON をまたいでも同じ確認として続ける。1 時間ごとに生存の行と復元できる checkpoint を出す。agent-health の日次の計測に観測だけの指標 `auto-yes-observation`（category `process`。Issue は立てない）を足し、窓の中の停止の時間（分）・ツール別・根拠の段別の回答数・理由別の停止の件数と時間を出す（計測区間が無い日は skip。公開に載せるのは件数・時間・ツール名・語彙だけ。`/prompt-response` の人の回答は Auto-Yes の回答数 `answered` に入れず `answeredByHuman` に数え、Auto-Yes の OFF で閉じた区間はその後の時間を数えない）。agy（antigravity）は `PreToolUse` の `stepIdx` から呼び出しの識別 `callId`（`<conversationId>:<stepIdx>`）を読み、受信で通した画面の確認に結び付けて、画面から消えた時点かその呼び出しの `PostToolUse` の早い方で閉じる（中継 `scripts/hooks/cmate-agent-event.sh` は agy の `post_tool_use` の本文に `stepIdx` を足す。`stepIdx` の無い古い本文も今までどおり受け付ける）。同じコマンドの 2 回の呼び出しは 2 件に数え、画面で確認を観測しないまま `PostToolUse` が来た要求は `dialogUnobserved` として記録する（利用者に見える変化は無く、記録の欄が増えるだけ）。記録する経路に `agy-link` が加わり全経路が揃うので、日次の `auto-yes-observation` はこの版の記録だけの日には部分計測（`partial`）にならない。**答え方は変えない**（記録とロガーの例外は回答・hook の返事・`/prompt-response` の応答に影響しない）。**利用者に見える履歴の変化: agy（antigravity）・command-code・gemini の hook の allow で、履歴に「Auto-Yes が許可した」行（`PermissionRequest allow · tool=…`）を書かなくなった** — これらは allow の後も確認を出すため、画面の回答の行と同じ承認を二重に書いていた。claude / codex / copilot / opencode は今までどおり書く。ソースの能力に `permissionAllowSuppressesDialog` を足し、CLI の `capture --json` の型と説明に載せた。設計は `docs/design/auto-yes-measurement-3820.md`。
