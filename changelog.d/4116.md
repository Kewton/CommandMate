- **feat(cli): CLI だけでロールの定義・既定・セッションの指定を完結させる** (#4116): `commandmate roles`（`list` / `show` / `add` / `edit` / `rm` / `default` / `defaults`）、`instances <wt> set-role`、`instances <wt> add --role | --no-role`、`send --role | --no-role` を追加。本文は `--file` か標準入力で渡し、改行と日本語をそのまま保存する。`<role>` は ID か名前で、候補が 2 つなら示して exit 2。予約語はなく「ロールなし」「既定に従う」はフラグで区別する。`--repo` は ID → パス（登録済み worktree はそのリポジトリを指すので `--repo .` が使える）→ 名前の順で読み、`unknown_repository` / `repository_not_registered` / `ambiguous_repository` を区別する。`roles default` / `roles edit` の `--json` は変更前後と影響範囲（Schedule にも及ぶこと）を返し、`instances --json` は起動時と次回のロールと source を返す。`send --role` は切り替えではなく条件で、設定を保存したうえで、起動時の fingerprint が一致するプロセスにだけ送る。不一致と不明は本文を入力せず exit 32。`send --register --role` はインスタンスとロールを送信の前に作るので最初の起動からそのロールで動く（`--role` なしの `--register` は従来の順序）。**固定条件が実入力まで届くようにした**: `send --expect-role-generation` / `--expect-role-fingerprint` / `--expect-no-role` を追加し、`launch-worker` は起動メッセージで読んだ世代と fingerprint を契約の送信に渡す。最後の確認の後に同じロールでプロセスが入れ替わっても新しい世代へ契約を送らない（exit 32 → `launch-worker` は停止して 44）。固定先のプロセスが止まっていれば新しく起動せず拒否する。**`POST /send` は保存の直前に名簿と宛先を読み直し**、待ちの間に変わっていれば 409（`roster_changed`、exit 31）で保存も送信もしない。ロールか固定を付けた送信が未入力で終わると、その送信が有効にした `--auto-yes` を取り消し、もともと有効だったものはそのまま残す。`--contract --role` は契約の検査が古い設定で拒否するときだけ保存して検査し直すので `send --role` と同じ結果になる。`launch-worker` はロールを持つサーバーで起動の証拠が無ければ契約を送らず止める。ロールか固定を付けた `--auto-yes` / `--contract` / `--reply-to` は宛先を省いても読んだ既定を全要求に名指しするので、途中で既定が変わっても別の対象の Auto-Yes を上書きも取り消しもしない。ロールを変える要求が 5xx か応答なしで終わると、保存の有無が不明であることと確かめるコマンドを伝える（`--json` は `saved: "unknown"` と `check`）。新しい終了コードは 31（競合）と 32（未入力）で、30（`interrupt`）と 40 / 41（厳密な `respond`）を避けた。
